# M7 — Language Forge 0.8.0

M7 adds a separate Language Forge tab beside the existing Workbench. The default launcher opens M7; `launch.bat --m6` retains M6.1. `setup.bat` installs the unchanged pinned runtime through `requirements/requirements-m7.txt`, audits it and runs all regressions. SQLite is part of Python; no server or new package is required.

## Independent language history

A `.vayforge` file contains a transactional SQLite project, named branches, durable working drafts, content-hashed immutable versions, and test-run records. A version freezes its dictionary, typed grammar, source citations, wiki, editorial decisions, research measurements and tests together. Branching starts from a frozen version and retains the previous branch's draft. Switching the version selector is read-only; branch from that version to edit it. Dictionary and wiki edits autosave after 700 ms, and Commit creates a named version. A stale writer is rejected using both project identity and generation. Reload draft offers recovery from a conflicting editor without silently replacing unsaved text.

Use **Export history** or `forge.export` for a portable JSON bundle containing all versions, drafts and run records. `forge.restore` verifies hashes and restores to a new path. This bundle does not contain fonts, source PDFs or rendered run files; retain the run folders and existing font-complete Workbench backups separately. Project files and local backups on the same disk are not independent-device backups. M7 has branching and typed diffs; merges and release acceptance remain future milestones.

Native Workbench format remains **0.5.0**, readable by M6.1. A generated test document embeds only its selected language dataset and pin, while the external run manifest records the Forge commit, wiki hash, test, template hash, renderer, document hash, proof hash and diagnostics. Opening a test launches a separate Workbench; the original book remains open. Editing that test does not mutate its language project or frozen run.

## Demonstration and linguistic scope

The private demonstration is `.local/demos/m7-forge-v0.8.0/Vayrshemon.vayforge`. It retains the original archive on `main` and two versions on `extrapolation-0.1`: **Vayrshemon 0.1.0 — source-derived proposal** and **0.1.1 — wiki and dictionary review**. The second version changes a wiki page and a dictionary entry; the first remains inspectable.

The dictionary has **751 records**: 733 archive witnesses and 18 explicitly proposed current spellings/lexemes. Parallel historical entries are retained, not deduplicated into fictitious certainty. The 12 wiki pages cover the source grammar, proposed clause order/case, tense/aspect, noun classes, pronouns, encoding, correlatives, lexical policy, frequencies and dictionary design. Proposed language has not been accepted by the author merely because the software can render it.

The proposal retains the seven-tense system and distinguishes tense from aspect. It chooses the table/transliteration reading of the conflicting immediate/distant future suffixes, preserving the competing witness. The pronoun chart confirms that “we(s)” is an explicit distinction; the branch proposes a collective-singular interpretation rather than treating it as a typo. Current spellings used in the test map named historical letters into the 79 inventory; unresolved IPA remains blank.

The novel two-paragraph test uses learning, reading, writing, remembering and a blue jewel. It exercises a bounded proposed subset with written derivations and an English translation. It is author-composed, not machine translation or an attested archival passage. The general grammar parser is explicitly **Unsupported**; proposed semantics remain **Needs review**. M8 is the executable linguistic test laboratory.

## Source coverage and frequency accounting

All 31 substantive DOCX documents are extracted by the existing preservation reader. The inventory also records the three legacy DOC files, six technical TXT files, one XPS and ten new dictionary PDFs. Historical font-slot counts remain separated by font family, with repeated exact runs deduplicated. Artificial alphabet/kerning specimens are excluded from natural-language counts. Legacy containers, inherited Word formatting and untranscribed native/raster material remain explicit gaps; M7 does not claim complete linguistic decoding of every archive image or InDesign/FontLab file.

The canonical running-text profile has **152 mapped letters** from the two polished witnesses. It folds maxima/minima only through the 47 symbol identities; Unicode case folding would corrupt these legacy slots. It reports unknown slots and keeps dictionary type counts separate from running-text counts. The proposed dictionary and novel paragraphs have independent profiles. This very small corpus does not establish population frequencies. The proposal favors existing roots and transparent inflections rather than inventing random words to fit an unreliable distribution.

The ten supplied dictionaries inform source attribution, stable senses, variant history, spelling/pronunciation separation, grammatical cross-references, examples and corpus-aware frequency reports. Review used extracted front matter through PDF page 14 and a rendered sample page from each; Middle Egyptian is scanned and was not fully OCRed. The hash/page manifest is versioned in `data/language/dictionary-inspiration.json`; PDFs, extracts and source-derived dictionary contents stay ignored. No English or other-language dictionary text contributes to Vayrshemon frequency counts.

## Protected presentation and test outcomes

The runner verifies the immutable approved reference before cloning it. It preserves the enlarged portrait page, margins, two frame geometries, 50 pt script, 18 pt English, exact 38/30 pt leading, 24 pt paragraph spacing, three-font registration, bevels and black-paper glow. Paired paragraph starts are measured and aligned with ordinary before-spacing. It does not change sizes to force a fit, add headings or resize overflowing text. Every run reports overflow and missing/fallback glyphs, conservative collisions, and the limits of linguistic validation separately.

The original approved page remains an exact geometry/pixel regression through `tools.approved_baseline` and `tests.test_m61`; the original 612 × 792 fixture remains covered by `test_parallel_translation.py`. A novel paragraph cannot have the same pixel hash as the original prose: its independent presentation signature excludes text but retains protected geometry, styles and paint. Expected baseline hashes are never regenerated.

## API, MCP and diagnostics

API **0.8.0** exposes **115 operations**, including 17 new Forge/workspace controls. Contracts are published in `schemas/forge-command.schema.json`, `data/forge-capabilities.json`, and `data/forge-mcp-tools.json`. Desktop edits, CLI, Python and MCP share the same dispatcher. Document identity/revision and idempotency guards still apply; language writes additionally require `project_id` and `expected_generation` from `forge.status`.

New operations: `forge.create`, `forge.open`, `forge.read`, `forge.status`, `forge.history`, `forge.diff`, `forge.draft.replace`, `forge.record.put`, `forge.commit`, `forge.branch`, `forge.checkout`, `forge.export`, `forge.restore`, `forge.test.run`, `forge.runs`, `forge.run.open`, and `ui.forge`. The UI supports normal dictionary/wiki edits; full typed grammar, source, test and dataset editing is available through the API. A dedicated visual test authoring form and general rule compiler are deferred to M8.

Headless MCP: `.venv\Scripts\python -m vayrshemon mcp --headless --forge`. Live MCP discovers 0.8.0 from the selected descriptor; pass `--descriptor` when several windows are open. Each command writes a correlated trace and complete exceptions to `.local/logs`. Run folders retain `run.json`, `layout.json`, `api-transcript.json`, the editable native book and its PNG proof. Separate test windows capture stdout/stderr to a unique desktop log. Never publish descriptor tokens or private source material.

Rebuild the local demo with `.venv\Scripts\python -m tools.m7_demo --out <new-directory>`. It refuses existing destinations, retains both language versions, edits the wiki and dictionary, runs the novel test and exports the history. It requires the local archive and private approved baseline; public persistence/UI/MCP tests use synthetic data when those inputs are absent.
