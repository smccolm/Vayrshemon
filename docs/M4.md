# M4 glyph studio and publishing

Application **0.5.2**, API **0.5.0**, native document **0.4.0**, paint engine **1.0.2**, recipe/state **1.0.0**. M4 implements the renderer, editable controls, color-font fallback compiler and publishing path. **VISUAL-01 remains pending user visual acceptance.** The review artifacts are candidates; automated tests do not approve their appearance.

Run `setup.bat`, then `launch.bat`. Use **View → Page focus** (or `launch.bat --page-focus`) for a clean, larger page preview; **View → Edit with diagnostics** restores source editing and troubleshooting panels. Setup installs the pinned NumPy, SciPy, Pillow and independent PDF proof renderer in addition to Qt and fontTools, checks dependencies and runs the complete suite including the approved parallel-translation tests. No Adobe application, GPU, Node or C/C++ compiler is required. `launch.bat --m3`, `--m2` and `python -m vayrshemon lab` retain earlier interfaces.

## Paint and source fidelity

The **Paint** tab applies the three-font treatment to Thimfora 79 selected in **Text**. The authoritative construction is `Inputs/font files/How to Make High Quality Color Text with Photoshop.txt`: 79 supplies the light-blue outline, 81 the dark-blue interior, and 80 the translucent outer glow. Glyph names, character mappings, units per em and advances must agree. Shape the master once; reuse its exact origin, baseline, size and page transform for every layer. Distinct layer bounds and side bearings must never be centered or normalized independently. Interior subpaths are additive, as specified by the Photoshop ADD operation.

Paint order is glow, interior, outline shadow, outline edge, outline. The glow mask never becomes an opaque fill or the source of the outline's shadow/stroke. The outline's shadow falls on the interior beneath it. `layout.inspect` reports every layer's source font/glyph, original side bearing, local bounds and shared page origin. `glyph.proof` supports `layer=composite`, `outline`, `interior` or `glow-mask`; all four use the same canvas, bounds and scale for direct registration checks.

The recipe controls blue rim and violet interior colors, highlight color, thin dark edge, em-relative bevel width/depth, light angle/elevation, vertical gradient, glow radius/opacity and shadow radius/offset/opacity. The treatment is computed from outlines; no reference JPG is used to paint text. Rendering uses antialiased outline masks, distance-field surface normals and finite Gaussian support. Cache keys include source bindings, glyph ID, size, complete recipe and device scale; cached tiles are bounded to 96 MiB and six million pixels each. Large glyph/DPI requests fail explicitly when a tile exceeds that budget.

The archived Jiam PSD supplies concrete reference measurements: blue overlay approximately RGB 6/116/218, 120° lighting at 30° elevation, bevel depth 164%, rim/interior sizes 30/65 px, 1 px dark stroke, and pale cyan glow at 56% opacity with a 51 px extent. These inform the versioned approximation. The renderer does not claim to reproduce Photoshop's proprietary bevel/contour blending exactly. The reference audit records the original asset hashes and comparison alignment.

The historical translation fixture uses `test seven` and one `transliteration 5` run. It remains an archival preservation test. The user rejected both its M4 single-font approximation and the 0.5.1 counter-only patch as the requested effect. The **derived** API binding is retained for generic single-font relief, but it is not the Individual Glyphs construction and is not offered by the three-font button.

The color review uses a separate [layered fixture](../data/formatting/parallel-translation-layered.json) with the actual 79/81/80 family. It keeps the paired passages, converts the old U+00BE clitic slot to U+2019 as evidenced by `Translation 1.psd`, and records every converted offset in a local manifest. Other source slots keep their scalar and matching glyph name. The original documents and old fixture are not rewritten. The canonical typeface uses 50 pt in this review, with 38 pt leading; English remains 18 pt. New outlines and advances change wrapping, and paired baselines are measured again. This is an explicit review copy, not an unchanged historical import or an approved visual baseline.

Engine version 1.0.2 is recorded separately from the unchanged recipe format in native provenance, preflight, glyph proofs and cache keys. Existing M4 documents remain compatible; historical derived bindings do not silently convert themselves to the three-font family.

The [three-layer validation record](research/m4-three-layer-validation.json) records the instruction-source hash, 107 passing tests, actual font registration, live MCP layer proof and remaining visual review.

Paint bindings and recipes are ordinary document state: versioned, validated, undoable, recoverable, and saved with font provenance. Migration from M1–M3 leaves original files intact and begins with no decorative binding. Monochrome mode retains the original outlines and text colors. Source editing, copying and searching use the native text, not a rendered picture.

## Bounds, layout and the standard page

M4 adds finite painted extents to each glyph before the existing collision solver runs. Choose **effect** bounds in **Typeset** to include glow/shadow clearance. Manually reserved M3 stroke/effect space still represents unpainted space; the report distinguishes it from M4 paint. Collision checks remain conservative axis-aligned bounds, not exact pixel intersections. A soft glow touching its neighbor can be intentional; it is reported without silently changing text or spacing.

The demonstration preserves the [standard portrait layout](FORMATTING.md): exactly two long independent columns, Vayrshemon left and English translation right, no title, headings or footer. Effects contribute bounds to inspect. The historical fixture's original ink-overhang warning remains relevant to that font; the new typeface's diagnostics are measured independently. Paired paragraph alignment remains explicit spacing, not automatic semantic translation alignment.

## Export and color fonts

The **Publish** tab sets white, black or transparent page backgrounds and raster DPI. PNG preserves alpha. Decorative SVG contains an embedded PNG with physical point dimensions; decorative PDF contains raster page proofs. Both require an explicit raster policy through the API, with a specified 72–600 DPI. Ordinary outline SVG remains available; unsupported decorative outline export fails instead of flattening silently. Monochrome PDF uses outlines. PDF supports multiple pages with independently specified dimensions, and transparent pages are proofed on white paper.

**These proof formats are not searchable text.** No semantic text or source-font subset is embedded. The preflight reports that fact, font availability/hash identity and `fsType` metadata, missing glyphs, frame overset, effect clipping, raster limits, page dimensions, background behavior and sRGB color limitations. This is an sRGB display/print proof workflow, without CMYK, ICC conversion, PDF/A, bleed or spot-color support. Use the native `.vay.json` for semantic text; searchable interoperable publishing remains future work.

**Build flat COLR font** is an explicit reduced treatment: COLR v0/CPAL supports the interior/rim flat fills. Bevel, gradient, edge, shadow and glow are listed as unsupported in its build manifest. The original monochrome glyphs, cmap, advances and shaping tables remain as fallback. The manifest contains source hashes, glyph mappings, palette, recipe/hash, compiler version, output hash and validation. Two builds from the same inputs produce identical TTF bytes. Independent FreeType rendering is exercised through Pillow. Full appearance is retained in the editor and raster proof path.

## Repeatable evidence and remaining review

Run `python -m unittest discover -s tests -v`. M4 tests cover recipe migration/round-trip/undo, unchanged source, actual effect bounds, collision repair, transparency/DPI, raster-policy rejection, SVG physical size, multi-page PDF, independent PDF pixels/text extraction, deterministic color-font builds, independent FreeType and desktop controls. With Inputs present, run `python -m tools.verify_m4`. It creates a fresh ignored `.local/demos/m4-*` folder containing the explicitly adapted three-font two-column document, source-adaptation manifest, registered individual-layer proofs, PNG/SVG/PDF proofs, independent PDF rendering, black-paper comparison, reading/detail/DPI/background specimens, generated color font/manifest, full API transcript, preflight and layout diagnostics. `--document` accepts an already prepared Thimfora 79 specimen; it rejects historical-font substitutes. The tool also hashes all 128 Individual Glyphs references and builds a reference/render/overlay gallery and contact sheets. Matched letter/numeral forms use the versioned orthography registry. Unverified historical punctuation stays labeled rather than receiving invented keyboard mappings. Uniform alignment of the complete three-layer glyph to the reference is recorded; the individual layers are never repositioned to improve the comparison.
