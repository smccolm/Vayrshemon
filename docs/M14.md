# M14 — .vay documents and Windows previews

Application **0.15.17**, API **0.15.0**, native wrapper **0.6.0**, saved preview **1**, paint engine **1.2.0**. M14 preserves the editable state schema, accepted typography, four-column alignment and Maxima. Save As now suggests `.vay`.

The bottom bar keeps **PNG**; **SVG** is available under **File → Export → SVG…**. The PNG button and all File → Export options start in `E:\Vayrshemon\Exports` (the project’s `Exports` folder). Setup and export dialogs create it as needed; Git ignores generated exports. You can still choose another destination. Both formats follow the visible page mode. One-page view suggests `YYYY-MM-DD_HH-MM-SS_mmm.svg` (or `.png`); two-page view exports a matching `_Left` / `_Right` pair from one timestamp and immutable document snapshot, even when the right page is selected. An unpaired final page produces only `_Left`. One dialog chooses the location/common stem, overwrite confirmation lists existing destinations, and cancellation covers both outputs. Monochrome SVG contains glyph outlines; decorative SVG embeds the page image at the chosen proof DPI. The Publish panel uses the same behavior. API/CLI/MCP `jobs.export` accepts `format: svg` with `page_ids` and optional `replace_sha256s`, just as for PNG.

**File → Export → PDF…** writes all physical pages to one `DateTimestamp.pdf` in `Exports`, regardless of the selected page. One-page view requests `/SinglePage`; two-page view requests `/TwoPageLeft` with left-to-right reading, pairing pages 1–2, 3–4 and leaving an odd final page alone. Decimal PDF page labels start at 1; no footer numbers or blank cover page are added. The PDF opens at its first page with Fit Page. Reader preferences may override the requested presentation.

PDF export preserves exact fractional page dimensions, margins, text, Maxima and color mode. Monochrome uses vector glyph outlines; bevel/glow pages use lossless images at the selected DPI. Existing proof limitations remain: glyphs are not searchable semantic PDF text. All pages, mode and opening view come from one frozen revision in a cancellable background job. The final destination is published only after rendering and PDF metadata succeed, with the existing overwrite/hash guards. API/CLI/MCP `jobs.export` and `publication.export` accept `pdf_view: one | two`; without it M14 uses the desktop arrangement or the saved page mode headlessly. Omitting `page_id` exports all pages.

Setup pins `pypdf==6.21.2` for viewing metadata and labels. `python -m tools.pdf_export_demo --source <save.vay> --out Exports` exercises the real menu/worker in six combinations without changing the source file, then renders independent Poppler PNGs under `.local/pdf-export-review/` and checks numbering, dimensions, exact protected state and matching single/double content streams. This optional review helper requires `pdftoppm` on PATH; normal PDF export does not require Poppler.

The 0.15.16 review covers all six combinations on the approved four-column example: black on white, white on black and color in both single and facing view. All 12 rendered pages were checked, corresponding single/facing renders match exactly, and the source save remains unchanged. Automated checks also cover three-page order and odd final pages, fractional dimensions, lossless color pixels, frozen snapshots, cancellation, changed-target overwrite protection, metadata failure and the approved parallel-translation regression.

**Language → Update transliteration** refreshes the existing Roman column from the Thimfora column in the current page/spread. It also works when the facing gloss/English page is selected, independently of one-page or two-page view. The old Reading copy controls are removed from the current ribbon. Columns must use the original Thimfora 79 and Transliteration 7 fonts and independent text frames; an English column is never automatically converted. If text differs, the desktop explains that direct Roman edits will be replaced and allows cancellation. One Undo restores both text and paragraph spacing. Already matching text creates no revision. Maxima/Minima slots are copied exactly, with no Unicode recasing or normalization; existing Roman styles, 22 pt / 38 pt typography, paint, geometry, and gloss/English text are retained. Corresponding paragraph starts follow the existing automatic alignment rules; count mismatch or overset pauses alignment without discarding the update. For a standalone two-column page, the update also aligns the pair.

API/CLI/MCP `page.transliteration.inspect` reports the affected frame IDs, paragraph counts, whether text differs and a `planId`. `page.transliteration.update` accepts that token as `expected_plan` to reject source/target changes since review, in addition to the normal revision/idempotency guards. Frozen M12/M13 interfaces and the legacy `page.reading.copy` API remain available.

Normal `launch.bat` startup hands off to `pythonw.exe` and closes the batch window immediately. The editor runs without a console, with Python and native stdout/stderr captured in a unique `.local/logs/launch-<timestamp>-<pid>.log`. Structured session `.jsonl` diagnostics remain available. Failures show a dialog pointing to the launch log; failures creating the log show their error directly. For a deliberately visible troubleshooting console, run `.venv\Scripts\python.exe -u -m vayrshemon editor` from a terminal. Setup checks the windowless interpreter; no additional dependency is required.

Save for a new document, Save As and Open start in `E:\Vayrshemon\Saves` (the project's `Saves` folder). Setup and file dialogs create it when needed; it is excluded from Git. Save As keeps the current filename as its suggestion, converting legacy suffixes to `.vay`. Ordinary Save continues updating an existing document at its current path. Existing files are not moved.

Source editor, diagnostics panel and page-guide visibility persist in `.local/workspace/layout.json`, separately from documents and the existing sidebar preferences. A fresh workspace hides all three for reading and defaults its controls panel to collapsed and unpinned. The approved first-run view opens Language Workbench with a blank white Untitled page fitted to height, Select active, Color / relief and single-page view selected. These defaults are shipped in application code and require no `.local` files. Existing sidebar and panel choices take precedence; setup does not reset them. Blank startup always selects one-page mode even if the previous session remembered two-page mode, and File → New also selects one-page mode. Saved `.vay` documents restore their own saved page arrangement, including direct launches. These automatic view choices do not overwrite the workspace page preference or add a document edit. View has individual checkable controls; Page focus, Edit with diagnostics, the source editor's × and API/MCP `ui.workspace` use the same preferences. Opening a saved document preserves its zoom, text, formatting and saved state. A new blank startup page is fitted after layout without marking it edited. The editor opens maximized, with normal menus and window controls, from both `launch.bat` and Explorer. `launch.bat` still opens a blank document; File → Recent documents reopens a save.

The title bar shows only the filename without its `.vay` extension (or legacy `.vay.json` / `.vaylab.json` suffix). A document without a save path shows Untitled. Unsaved state remains in the status bar and close prompt; the title has no app name or extra markers. Internal document titles and Forge identifiers remain metadata. Save As and opening another file update the displayed filename.

## Saved appearance

The running application uses the centered color Memon icon and the stable Windows taskbar ID `Vayrshemon.LanguageWorkbench`. Startup sets this before creating Qt windows, following Microsoft's [AppUserModelID initialization guidance](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shlobj_core-setcurrentprocessexplicitappusermodelid). Both `launch.bat` and Explorer use this path. Restart previously open windows to adopt it. Application identity is independent of each document's saved-mode icon described below.

The centered Memon capital is based on `Maxima_28_Memon.jpg`. Its three original font outlines share one origin; the complete glyph, including its descending curl, is centered by visible ink bounds. Icons include 16–256 px sizes. Color mode uses the blue bevel/glow on black, white-on-black Monochrome uses white Memon on black, and black-on-white Monochrome uses black Memon on white.

Explorer's small-icon view selects the icon from the file's **saved** mode. Thumbnail views display the saved page or facing spread. Unsaved edits do not affect either. Changing the mode or one/two-page view and pressing Save refreshes that file's preview. Existing Explorer thumbnail preferences remain respected.

The preview is an embedded PNG, up to 1024 px on its longest edge, rendered by the same page renderer with guides/diagnostic overlays excluded. Two-page mode captures the visible pair in reading order with a transparent gutter; one-page mode captures the selected page. It is a browsing preview, not a replacement for the full-resolution PNG export. No sidecar file or external font is needed to show it on another Windows PC with this component installed.

## Compatibility and persistence

`.vay` remains UTF-8 JSON. The 0.6 wrapper adds `shellPreview` containing the saved revision, canonical state hash, mode, page IDs, image dimensions, PNG hash and base64 pixels. Text, source codepoints, Maxima, paint recipes, geometry and language records stay in `state`. Ordinary native files reference fonts; verified `.vaybackup` bundles include declared fonts.

M14 opens original `.vaylab.json` and native 0.1–0.5 `.vay.json` files. Save As converts the suggested suffix without renaming the original. M1–M4 imports retain their new-path migration policy. M5–M13 state is preserved exactly; saving writes the new wrapper. Older applications cannot read 0.6, so retain originals or backups for rollback. Nothing associates all `.json` files with this app.

Preview generation must finish before the atomic save. A failed preview or a changed destination preserves the previous file and unsaved edit. New files use exclusive creation; replacement saves recheck the destination hash after rendering. The native file remains bounded to 16 MiB and the embedded PNG to 3 MiB. Opening validates the image hash, dimensions and state/revision correspondence before replacing the current document. Recovery verifies 0.6 backups and recalculates the state hash when relocating verified font paths; it preserves preview pixels.

## Installation and removal

Run `setup.bat` with Python 3.12 x64 installed. It verifies the four bundled application fonts and installs the pinned M14 Python requirements, including pypdf for PDF reading views. Setup also installs Microsoft Visual Studio C++ Build Tools/Windows SDK through winget when absent, builds the x64 COM DLL, runs the complete regression suite and installs Explorer integration. It reports failures and retains the transcript in `.local/logs/`.

The required Thimfora 79/80/81 and Transliteration 7 originals ship in `data/runtime-fonts/` with a hash/size/provenance manifest. Startup uses these files, independently of `Inputs`; Qt registers them only inside the application. Existing documents keep valid external font paths. Missing paths to these four exact font identities resolve to the bundled copy; changed files or explicitly supplied invalid replacement paths still fail validation. No glyph, case mapping, metric, layout or paint recipe changes. `python -m tools.verify_runtime_fonts` checks these assets without installing anything. Release bundles include and require them. The private Inputs archive, Saves and Exports remain ignored.

The native component lives in a versioned folder under `C:\Program Files\VayrshemonShell`. Windows administrator approval is needed for its first installation or an updated binary/icon set. An unchanged component is reused. Only its own COM class is registered machine-wide; `.vay` associations and the quoted open command remain per-user. This split was needed on the tested Windows 11 host: per-user icon extraction worked, while isolated Explorer thumbnail activation returned `REGDB_E_CLASSNOTREG` until the machine class was installed. Process isolation remains enabled.

The component reads bounded embedded data and decodes PNG through Windows Imaging Component. It does not launch Python, load fonts, render documents or execute document content. Native sources and reproducible icon geometry are included in the source release. Build outputs are content addressed so an Explorer-loaded DLL is never overwritten.

```powershell
.venv\Scripts\python -m tools.windows_shell            # inspect installation
.venv\Scripts\python -m tools.windows_shell --install  # repair/build/install
.venv\Scripts\python -m tools.windows_shell --unregister # per-user associations only
.venv\Scripts\python -m tools.windows_shell --uninstall  # associations + system COM class
```

Removal restores only values still matching this installation, using its registration journals. System removal asks Windows for administrator approval. Loaded versioned files are retained inert rather than forcing Explorer to unload them. An existing association chosen by another application is not replaced; Vayrshemon remains available through Open With. Explorer-open failures show a message with a log under `.local/logs/open-*.log`.

## Controls and verification

All **155** commands are published in `data/file-mcp-tools.json` and `schemas/file-command.schema.json`. `document.save` and `document.save-as` accept optional `preview_mode: one | two`; desktop saves use the visible arrangement, while headless saves reuse the last saved arrangement or default to one. `document.saved-preview` inspects metadata from disk without returning image bytes. `shell.status` is read-only. Headless MCP can select M14 with `mcp --files`; normal live MCP discovers M14 automatically.

The M14 suite exercises six mode/arrangement combinations, legacy migrations, failed saves, external edits during rendering, invalid previews, font-complete backup relocation, native dialogs/contracts and the real C++ provider including malformed inputs. The approved four-column demonstration was saved in all three modes; both 144-DPI page proofs matched the prior M13 renderer pixel for pixel. Native Windows Shell extraction was additionally checked through `IShellItemImageFactory`, covering all three icons and saved page/spread thumbnails.

The full setup suite includes the required attested parallel-translation fixture. Existing ink-overhang diagnostics remain visible; preserving the approved page does not imply that every legacy collision/overhang is zero. Private proofs, other archival fonts and documents remain ignored under `.local/` and `Inputs/`; only the four required application fonts are bundled in `data/runtime-fonts/`.

Microsoft's [thumbnail provider guidance](https://learn.microsoft.com/en-us/windows/win32/shell/thumbnail-providers) and [provider implementation guidance](https://learn.microsoft.com/en-us/windows/win32/shell/building-thumbnail-providers) document the isolated stream-based thumbnail path. [IExtractIconW::GetIconLocation](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-iextracticonw-geticonlocation) supplies the per-instance icon path used here.
