## Compatibility and persistence

`.vay` remains UTF-8 JSON. The 0.6 wrapper adds `shellPreview` containing the saved revision, canonical state hash, mode, page IDs, image dimensions, PNG hash and base64 pixels. Text, source codepoints, Maxima, paint recipes, geometry and language records stay in `state`. Ordinary native files reference fonts; verified `.vaybackup` bundles include declared fonts.

M14 opens original `.vaylab.json` and native 0.1–0.5 `.vay.json` files. Save As converts the suggested suffix without renaming the original. M1–M4 imports retain their new-path migration policy. M5–M13 state is preserved exactly; saving writes the new wrapper. Older applications cannot read 0.6, so retain originals or backups for rollback. Nothing associates all `.json` files with this app.

Preview generation must finish before the atomic save. A failed preview or a changed destination preserves the previous file and unsaved edit. New files use exclusive creation; replacement saves recheck the destination hash after rendering. The native file remains bounded to 128 MiB and the embedded PNG to 3 MiB. Opening validates the image hash, dimensions and state/revision correspondence before replacing the current document. Recovery verifies 0.6 backups and recalculates the state hash when relocating verified font paths; it preserves preview pixels.

## Installation and removal

Run `setup.bat`. It reuses the existing environment; for a new environment it locates Python 3.12 x64 and installs it automatically if absent. It verifies the four bundled application fonts and installs the pinned M14 Python requirements, including pypdf for PDF reading views. Setup also installs Microsoft Visual Studio C++ Build Tools/Windows SDK through winget when absent, builds the x64 COM DLL, runs the complete regression suite and installs Explorer integration. It reports failures and retains the transcript in `.local/logs/`.

The Python bootstrap uses the [official Python 3.12.10 x64 installer](https://www.python.org/downloads/release/python-31210/) and [documented unattended options](https://docs.python.org/3.12/using/windows.html#installing-without-ui). Its SHA-256 is pinned from the release's Sigstore metadata; setup also checks the Windows publisher signature for Python Software Foundation before execution. Downloads and installer logs stay in `.local/`. Installation is per-user, without changing PATH, adding Python file associations, installing the launcher or replacing an existing Python312 directory. Setup validates the resulting interpreter before creating `.venv`. Internet access is needed when downloading the missing interpreter and dependencies. Existing environments skip this bootstrap entirely.

Successful setup creates `Vayrshemon.lnk` on the current user's Windows Desktop, targeting this checkout's `launch.bat` with the centered color Memon icon and the project as its working directory. The brief batch window starts minimized. Repeating setup refreshes a shortcut targeting this installation and preserves a same-named shortcut pointing elsewhere. Run `powershell -NoProfile -ExecutionPolicy Bypass -File tools\create_shortcut.ps1` to create just the shortcut without running setup. The 0.15.18 validation uses mocked Python installer calls and actual shortcut checks; it does not reinstall Python or the application.

The required Thimfora 79/80/81 and Transliteration 7 originals ship in `data/runtime-fonts/` with a hash/size/provenance manifest. Startup uses these files, independently of `Inputs`; Qt registers them only inside the application. Existing documents keep valid external font paths. Missing paths to these four exact font identities resolve to the bundled copy; changed files or explicitly supplied invalid replacement paths still fail validation. No glyph, case mapping, metric, layout or paint recipe changes. `python -m tools.verify_runtime_fonts` checks these assets without installing anything. Release bundles include and require them. The private Inputs archive, Saves and Exports remain ignored.

The native component lives in a versioned folder under `C:\Program Files\VayrshemonShell`. Windows administrator approval is needed for its first installation or an updated binary/icon set. An unchanged component is reused. Only its own COM class is registered machine-wide; `.vay` associations and the quoted open command remain per-user. This split was needed on the tested Windows 11 host: per-user icon extraction worked, while isolated Explorer thumbnail activation returned `REGDB_E_CLASSNOTREG` until the machine class was installed. Process isolation remains enabled.

The component reads bounded embedded data and decodes PNG through Windows Imaging Component. It does not launch Python, load fonts, render documents or execute document content. Native sources and reproducible icon geometry are included in the source release. Build outputs are content addressed so an Explorer-loaded DLL is never overwritten.

```powershell
.venv\Scripts\python -m tools.windows_shell            # inspect installation
.venv\Scripts\python -m tools.windows_shell --install  # repair/build/install
.venv\Scripts\python -m tools.windows_shell --unregister # per-user associations only
.venv\Scripts\python -m tools.windows_shell --uninstall  # associations + system COM class
```

Removal restores only values still matching this installation, using its registration journals. System removal asks Windows for administrator approval. Loaded versioned files are retained inert rather than forcing Explorer to unload them. An existing association chosen by another application is not replaced; Vayrshemon remains available through Open With. Explorer-open failures show a message with a log under `.local/logs/open-*.log`.

## Controls and verification

Native books (0.15.30) retain the original editable page state. Files of 100 or more pages use a 0.7 JSON envelope containing bounded, checksummed zlib-compressed 0.6 state and an uncompressed saved preview. Small files remain 0.6; earlier files still open. Limits are 32,768 pages, 65,536 frames, 32 million text scalars, 1.5 GiB compact expanded state, 256 MiB compressed state and 384 MiB physical file. These are validation ceilings, not a promise of constant memory use or fast rendering at every ceiling. Older builds cannot read the compressed envelope. Setup updates the native component; Explorer reads at most an 8 MiB preview header rather than the whole document.

Recovery and export snapshots use the same bounded codec. The standard-library recovery command works with Python site packages disabled. Saves preserve exact prior wire bytes in history, enforce no-clobber and external-edit checks, and publish only a complete stream. Hashes remain compatible with earlier native state. An actual 1,178-page Bible checkpoint shrank from 125,384,220 to 11,153,072 bytes in a separate verification copy, with exact state/history and identical checked page rasters. The source was unchanged. A separate structural test exceeded all three former page/frame/text limits and exercised navigation, editing, Undo/Redo, compressed recovery and save/reopen.

For more than 100 pages, native frame editors load on demand; reading retains at most 16, except a larger explicitly connected flow component. Page selection updates only the reading position, guard revision and in-memory checkpoint position. Full recovery remains on content edits, save and clean close; a crash during reading may return to the last durable reading position, without losing edits. Undo, automatic paragraph alignment, shaping and painting retain the existing pipeline. Opening and saving a large book still validates the complete file and may take longer than turning a page.
