# M14 — .vay documents and Windows previews

Application **0.15.2**, API **0.15.0**, native wrapper **0.6.0**, saved preview **1**, paint engine **1.2.0**. M14 preserves the editable state schema, accepted typography, four-column alignment and Maxima. Save As now suggests `.vay`.

Source editor, diagnostics panel and page-guide visibility persist in `.local/workspace/layout.json`, separately from documents and the existing sidebar preferences. A fresh workspace hides all three for reading. View has individual checkable controls; Page focus, Edit with diagnostics, the source editor's × and API/MCP `ui.workspace` use the same preferences. Restoration does not fit the page or alter its zoom, text, formatting or saved state. `launch.bat` still opens a blank document; File → Recent documents reopens a save.

## Saved appearance

The running application uses the centered color Memon icon and the stable Windows taskbar ID `Vayrshemon.LanguageWorkbench`. Startup sets this before creating Qt windows, following Microsoft's [AppUserModelID initialization guidance](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shlobj_core-setcurrentprocessexplicitappusermodelid). Both `launch.bat` and Explorer use this path. Restart previously open windows to adopt it. Application identity is independent of each document's saved-mode icon described below.

The centered Memon capital is based on `Maxima_28_Memon.jpg`. Its three original font outlines share one origin; the complete glyph, including its descending curl, is centered by visible ink bounds. Icons include 16–256 px sizes. Color mode uses the blue bevel/glow on black, white-on-black Monochrome uses white Memon on black, and black-on-white Monochrome uses black Memon on white.

Explorer's small-icon view selects the icon from the file's **saved** mode. Thumbnail views display the saved page or facing spread. Unsaved edits do not affect either. Changing the mode or one/two-page view and pressing Save refreshes that file's preview. Existing Explorer thumbnail preferences remain respected.

The preview is an embedded PNG, up to 1024 px on its longest edge, rendered by the same page renderer with guides/diagnostic overlays excluded. Two-page mode captures the visible pair in reading order with a transparent gutter; one-page mode captures the selected page. It is a browsing preview, not a replacement for the full-resolution PNG export. No sidecar file or external font is needed to show it on another Windows PC with this component installed.

## Compatibility and persistence

`.vay` remains UTF-8 JSON. The 0.6 wrapper adds `shellPreview` containing the saved revision, canonical state hash, mode, page IDs, image dimensions, PNG hash and base64 pixels. Text, source codepoints, Maxima, paint recipes, geometry and language records stay in `state`. Ordinary native files reference fonts; verified `.vaybackup` bundles include declared fonts.

M14 opens original `.vaylab.json` and native 0.1–0.5 `.vay.json` files. Save As converts the suggested suffix without renaming the original. M1–M4 imports retain their new-path migration policy. M5–M13 state is preserved exactly; saving writes the new wrapper. Older applications cannot read 0.6, so retain originals or backups for rollback. Nothing associates all `.json` files with this app.

Preview generation must finish before the atomic save. A failed preview or a changed destination preserves the previous file and unsaved edit. New files use exclusive creation; replacement saves recheck the destination hash after rendering. The native file remains bounded to 16 MiB and the embedded PNG to 3 MiB. Opening validates the image hash, dimensions and state/revision correspondence before replacing the current document. Recovery verifies 0.6 backups and recalculates the state hash when relocating verified font paths; it preserves preview pixels.

## Installation and removal

Run `setup.bat`. The pinned Python dependencies are unchanged from M13. Setup also installs Microsoft Visual Studio C++ Build Tools/Windows SDK through winget when absent, builds the x64 COM DLL, runs the complete regression suite and installs Explorer integration. It reports failures and retains the transcript in `.local/logs/`.

The native component lives in a versioned folder under `C:\Program Files\VayrshemonShell`. Windows administrator approval is needed for its first installation or an updated binary/icon set. An unchanged component is reused. Only its own COM class is registered machine-wide; `.vay` associations and the quoted open command remain per-user. This split was needed on the tested Windows 11 host: per-user icon extraction worked, while isolated Explorer thumbnail activation returned `REGDB_E_CLASSNOTREG` until the machine class was installed. Process isolation remains enabled.

The component reads bounded embedded data and decodes PNG through Windows Imaging Component. It does not launch Python, load fonts, render documents or execute document content. Native sources and reproducible icon geometry are included in the source release. Build outputs are content addressed so an Explorer-loaded DLL is never overwritten.

```powershell
.venv\Scripts\python -m tools.windows_shell            # inspect installation
.venv\Scripts\python -m tools.windows_shell --install  # repair/build/install
.venv\Scripts\python -m tools.windows_shell --unregister # per-user associations only
.venv\Scripts\python -m tools.windows_shell --uninstall  # associations + system COM class
```

Removal restores only values still matching this installation, using its registration journals. System removal asks Windows for administrator approval. Loaded versioned files are retained inert rather than forcing Explorer to unload them. An existing association chosen by another application is not replaced; Vayrshemon remains available through Open With. Explorer-open failures show a message with a log under `.local/logs/open-*.log`.

## Controls and verification

All **153** commands are published in `data/file-mcp-tools.json` and `schemas/file-command.schema.json`. `document.save` and `document.save-as` accept optional `preview_mode: one | two`; desktop saves use the visible arrangement, while headless saves reuse the last saved arrangement or default to one. `document.saved-preview` inspects metadata from disk without returning image bytes. `shell.status` is read-only. Headless MCP can select M14 with `mcp --files`; normal live MCP discovers M14 automatically.

The M14 suite exercises six mode/arrangement combinations, legacy migrations, failed saves, external edits during rendering, invalid previews, font-complete backup relocation, native dialogs/contracts and the real C++ provider including malformed inputs. The approved four-column demonstration was saved in all three modes; both 144-DPI page proofs matched the prior M13 renderer pixel for pixel. Native Windows Shell extraction was additionally checked through `IShellItemImageFactory`, covering all three icons and saved page/spread thumbnails.

The full setup suite includes the required attested parallel-translation fixture. Existing ink-overhang diagnostics remain visible; preserving the approved page does not imply that every legacy collision/overhang is zero. Private proofs, fonts and documents remain ignored under `.local/` and `Inputs/`.

Microsoft's [thumbnail provider guidance](https://learn.microsoft.com/en-us/windows/win32/shell/thumbnail-providers) and [provider implementation guidance](https://learn.microsoft.com/en-us/windows/win32/shell/building-thumbnail-providers) document the isolated stream-based thumbnail path. [IExtractIconW::GetIconLocation](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-iextracticonw-geticonlocation) supplies the per-instance icon path used here.
