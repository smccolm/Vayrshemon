# M6 reliability and navigation — 0.7.0

M6 adds Select and Hand tools, bounded incremental shaping, cancellable proof workers, portable font-complete backups, an offline recovery utility and versioned Windows installation/rollback. Application/API **0.7.0**, reliability bundle **1.0.0**. Native documents remain **0.5.0**, readable by M5. Language packages and paint engine are unchanged.

## Use the editor

Run `setup.bat`, then `launch.bat`. The preview toolbar has **Select**, **Hand**, **Center page** and **Fit page**. Select says “Click a frame to edit” and reveals the source editor on a frame click. Hand drags the view with the left button, including when the page fits the viewport. Middle-button dragging also works. Switching tools and panning do not modify document content, revision, saved state or undo history. Zoom retains its existing saved-document behavior.

Keyboard: **Ctrl+Alt+H** selects Hand, **Ctrl+Alt+V** selects Select. With preview focus, use H/V, hold Space for temporary Hand, use arrows to pan and Home to center. Text fields retain ordinary H/V/Space typing. Controls expose accessible names, focus and checked state. Automated Qt events/provider checks do not replace a physical screen-reader, IME or multi-monitor assessment; those M1 checks remain open.

PNG, SVG proof and Publish exports suggest date-and-time filenames. These M6 buttons start an isolated proof worker and leave the editor responsive. The Reliability panel shows state, revision, log path and Cancel. An export is a snapshot: editing afterward marks it stale, without altering its source. One worker runs per editor; 64 job records are retained per session. Cancellation terminates only that worker and never publishes a partial destination. An existing destination, including one created during rendering, is preserved. Errors and full worker traceback output remain in `.local/jobs/job.*/worker.log`; state/progress are inspectable via API/MCP.

## Backups and recovery

Every successful native save attempts a separate verified `.local/backups/<document-sha256>.vaybackup`. The bundle includes the exact native file, every declared source font and a member/hash manifest. Duplicate saves share the same bundle; all distinct saved revisions are retained, with no automatic deletion. A backup failure is reported separately from the already-completed document save, in session status, logs and the status bar.

These local backups are independent of Git and the live file, **but share the same disk**. Reliability → Back up saved document lets you choose another destination. No external destination or upload is enabled automatically. This covers document/font recovery, not a separate backup of the entire Inputs archive.

The recovery utility needs only Python's standard library, even when Qt or the application environment is broken:

```powershell
python -S tools/recovery.py inspect path/to/document.vay.json
python -S tools/recovery.py text path/to/document.vay.json --out exact-runs.json
python -S tools/recovery.py verify path/to/snapshot.vaybackup
python -S tools/recovery.py restore path/to/snapshot.vaybackup --out NEW-folder
```

Recovery verifies hashes, member names, sizes and font identities **before** creating a new destination. It retains `original.vay.json` byte-for-byte, writes relocated fonts and `recovered.vay.json`, and records both hashes. It never replaces an existing folder. Open the recovered document for full schema/semantic validation; the offline inspector explicitly reports its structural-only validation scope. Keep the original and recovery report together.

## Windows installation, update and rollback

The M6 installer is a versioned **source installation**, bootstrapped by Python 3.12 x64. It is not a signed MSI or a self-contained Python executable. All installation artifacts stay at the directory explicitly supplied. It makes no registry changes and needs no administrator access. Setup installs pinned binary wheels, audits their metadata/notices, runs evidence checks and the complete public test suite. Activation happens only after those checks succeed.

```powershell
installed.bat build --out .local/releases/m6.zip
installed.bat verify .local/releases/m6.zip
installed.bat install .local/releases/m6.zip --directory E:/Vayrshemon/.local/installed
installed.bat launch --directory E:/Vayrshemon/.local/installed
installed.bat status --directory E:/Vayrshemon/.local/installed
installed.bat rollback --directory E:/Vayrshemon/.local/installed
```

An update installs a new content-addressed directory and atomically switches `active.json`; the previous installation remains available. Rollback verifies the earlier source files before switching back. Open windows continue their existing version. Documents are never moved, downgraded or deleted. Old native formats retain their existing migration-to-a-new-path rule; M5/M6 share native 0.5.0.

To install offline, first download the pinned wheels using `pip download --only-binary=:all: -r requirements/requirements-m6.txt --dest WHEELHOUSE`, then add `--wheelhouse WHEELHOUSE` to install. Direct setup also accepts `VAYRSHEMON_WHEELHOUSE`. A failed setup remains resumable and never replaces the active installation. Bundle hashes verify integrity, not publisher authenticity; only install trusted bundles.

## Performance and limits

Layout is scoped to the requested page and its connected flow pages. Unchanged stories reuse owner-thread Qt shaping; geometry, leading and collisions are recomputed for the affected page component. Cache bounds: two composed page components, 64 shaped stories / 20,000 cached glyphs / 10,000 cached lines, and the existing 96 MiB paint-tile cache. Offscreen glyphs are culled before generating paint tiles. Hidden inspectors stop generating reports on every edit. A page/connected flow component retains the 20,000 positioned-glyph bound; one enabled story retains the 30,000-scalar bound.

The reproducible [benchmark](research/m6-performance.json) uses 100 independent pages, 100,000 synthetic scalars and the platform system font. Ten local edits rebuilt ten stories, not the whole document. On the recorded Windows/AMD machine, p95 API-edit-through-page-paint was **247 ms**, and p95 pan-and-paint was **11.9 ms**. The provisional 50 ms edit budget remains unmet; full-state capture, validation and undo still scale with document size. This is an API/event-pump measurement with recovery disabled, not a physical input-latency claim. Recovery and large language revision graphs can add work. Peak working set and private commit are reported separately in the evidence.

A 10,000 × 12,000 pt decorative page rendered a 1,200 × 1,200 pixel region using the actual three-font treatment. Full rasters remain limited to **16 million pixels and 32,767 pixels per axis**; arbitrary native dimensions do not imply unbounded raster allocation. Long single paragraphs and heavily connected pagination remain future optimization work. M6 is not a claim that all production-scale performance or physical accessibility gates have passed.

## API, MCP and interchange

M6 publishes 96 guarded operations in [the MCP registry](../data/reliability-mcp-tools.json) and [command schema](../schemas/reliability-command.schema.json). Additions: `view.tool`, `view.pan`, `view.center`, `view.inspect`, `performance.inspect`, `backup.create`, `backup.verify`, `backup.restore`, `jobs.export`, `jobs.status`, `jobs.cancel`. Mutations keep the document/revision/idempotency guard, including operations that do not alter the document.

Headless: `python -m vayrshemon mcp --headless --reliability --no-source-fonts`. Live MCP discovers API 0.7.0. `launch.bat --m5` retains the previous language interface. [Interchange](INTERCHANGE.md) documents semantic native/JSON versus visual PNG/SVG/PDF exports and exact source recovery.

The [dependency inventory](research/m6-dependencies.json) audits 12 pinned distributions and hashes their installed license notices. NumPy/SciPy include bundled numerical-library notices; PySide6/Shiboken expose LGPL/GPL alternatives; pypdfium2 includes PDFium third-party terms. Setup preserves upstream distributions and notices. This source bundle does not contain dependency wheels, Python, private fonts or Inputs; a future binary redistribution needs its own packaging review.

## Demonstration and evidence

The M6 demo uses the standard black portrait page with exactly two independent full-height columns, actual 79/81/80 lettering on the left and pale English on the right. `tools.m6_demo` copies the live source through read-only API calls, preserves pages, paint and language data, then saves a separate M6 file. It leaves the user's open M5 session, including unsaved changes, untouched.

`tests/test_m6.py` exercises actual Qt dragging/key events, selection return, saved-state preservation, cache scope/reuse, source-font-independent recovery, tampered bundles, backup failures, worker cancellation, stale snapshots, destination races, failed renders, timestamps, guarded tools and release rollback. The full setup includes the required standard parallel-translation suite. Final run and clean-install evidence are recorded in [M6 validation](research/m6-validation.json). Final M4 VISUAL-01 acceptance remains separate and open.
