# M8 — Executable Language Forge tests, 0.9.0

M8 adds a finite rule compiler, a test authoring workspace, coverage, pinned version comparisons and a Shakespeare demonstration. `setup.bat` installs the same pinned runtime through `requirements/requirements-m8.txt` and runs the full regression suite. No new external dependency is needed. The default launcher opens M8; `launch.bat --m7` retains the earlier Forge interface, and the older Workbench modes remain available.

## Author and run tests

Open **Language Forge → Laboratory**. Select **Test cases**, **Rules** or **Bilingual pages**. New creates a draft record; Save draft validates and persists it with the project's identity/generation guard. Edits are saved before changing records, versions or closing the window. A failed validation or stale writer retains the form contents. Historical versions are read only. Dictionary/wiki autosave and the Workbench retain their existing behavior.

Cases have a stable ID, title, kind, input, expected outcome, rule IDs, editorial note and optional token annotations. Word tests analyze the entire word. Clause tests require ordered, nonoverlapping **Unicode-scalar** spans, lexical IDs, grammatical roles and feature maps; unconsumed non-punctuation text is rejected. The compiler checks the surface against the annotated lexical identity/features, then checks role order and any role-specific lexical/case constraints. It does not infer annotations from prose.

Bilingual page authoring has separate Vayrshemon, English and analysis fields. Blank lines separate paired paragraphs; single newlines become soft verse line breaks in the generated document. Paragraph counts must agree. Optional `caseIds` lists bind each script paragraph to complete, ordered clause inputs (joined by a space); mismatched page text is rejected. Unbound prose is explicitly reported as untested by this check. **Tests → Run frozen version in Workbench** runs the language suite and creates a separate book using the approved presentation; it never replaces the current book. Save/commit before reproducible runs, or use Preview draft for a clearly labeled transient evaluation.

## Supported rules and boundaries

Rules link to stable grammar records and freeze alongside the dictionary, wiki and cases:

| Kind | Configuration and execution |
| --- | --- |
| `inventory` | `orthographyId`, `extraCharacters`; checks actual scalar slots against the versioned orthography. No Unicode case folding or inferred pronunciation. |
| `forms` | `entryIds`, `prefixes`, ordered `slots` of `feature`/`values`; enumerates finite literal inflections, retaining every analysis of ambiguous spellings. |
| `analysis` | `formRuleIds`; combines named finite paradigms for exhaustive clause-token analysis. |
| `order` | `patterns` of role names; optional `roleEntries` and `roleFeatures` constrain the lexeme and exact feature map allowed in each role. |
| `review` | `reason`; records an editorial question which cannot become a mechanical Pass. |

Configuration is declarative JSON. No user Python, arbitrary regular expressions or network execution. Limits include 1,000 rules/cases per collection, six suffix slots, 50,000 forms per paradigm, 100,000 total generated forms, 200,000 combined analysis records, 128 alternatives per surface and an 8 MiB result budget. Unknown-scalar/unconsumed-offset diagnostics retain counts and a bounded sample. This is an inspectable finite compiler, not a general parser, translator or phonology engine.

Expected outcomes are `accept`, `reject`, `review`, and `unsupported`. A deliberate invalid input earns Pass only when it is actually rejected; unexpected acceptance is Fail. An expected review remains **Needs review**, and expected unsupported behavior remains **Unsupported**. Empty suites are Unsupported. Coverage counts passing positive and negative assertions separately, excludes editorial/unsupported cases and lists grammar records without executable rules. A positive-only rule is visibly partial coverage.

Version comparison runs **the exact same frozen case definitions** against two language versions. By default these cases come from the before version; the API can specify a third case version. Reports include each case hash, actual outcomes, expectation changes, regressions and improvements. Changing test expectations in the later branch cannot silently erase a regression. Comparisons are computed on demand; suite runs are appended to project history and saved as JSON manifests.

## Literary demonstration

The private project is `.local/demos/m8-forge-v0.9.0-final/Vayrshemon.vayforge`, restored from the M7 history into a new destination. M7 versions and its original project remain intact. Branch `literary-0.2` contains **0.2.0 — literary experiment before enumeration** **0.2.1 — scoped poetic enumeration**, **0.2.2 — explicit event nominalization**, and **0.2.3 — proof bound to tested clauses**. The first version deliberately exposes the unsupported multi-subject construction; the second adds a declared list of 2–8 subjects, retaining the existing single-subject forms and the unchanged test expectations.

The page uses Prospero's speech from “Our revels now are ended” through “Is rounded with a sleep,” *The Tempest*, Act 4 scene 1, lines 165–175 in the [Folger text](https://www.folger.edu/explore/shakespeares-works/the-tempest/read/4/1/). The English is the starting point and preserves its words, punctuation and verse breaks, with paragraph divisions grouping the three images. Narrow columns may wrap a verse line. The caption supplies attribution without adding a heading or footer to the approved page.

The left column is an explicitly proposed literary adaptation. It derives vocabulary from cited roots and recorded historical-slot conversions; compounds such as sleep-see-form carry dreamlike constitution. The wiki records back-translations, new morphology, semantic compression and losses. For example, “little life” becomes fragile life and “rounded” becomes surrounded; the repeated breath image interprets melting into thin air. These are editorial choices awaiting the language author's review. No mechanical test certifies Shakespearean equivalence, metre or the truth of a lexical interpretation. Frequency accounting remains by semantic letter identity and is compared with the tiny existing sample without fabricating a target distribution.

The suite contains **57 cases: 55 Pass, one Needs review and one Unsupported**, with no unexpected failures in 0.2.3. The earlier enumeration assertion fails and then passes in the same-case comparison. Version 0.2.2 restores the source-derived ef’ event-nominalizer on sleep/breath and corrects foretell to a verb. Running 0.2.1’s unchanged cases against 0.2.2 flags the two older unmarked constructions as regressions; those are intentional compatibility changes, retained visibly rather than hidden by updating expectations. Version 0.2.3 also ties the displayed script to those exact assertion inputs, correcting an unintended prefix replacement on the lexicalized dream-form compound. The page has **zero overflow, zero missing/fallback glyphs and 27 conservative collision warnings**. Those warnings remain inspectable; this is not a zero-collision claim.

## Presentation, persistence and diagnostics

The enlarged 865.498700 × 1120.057141 pt page, margins, independent two-column frames, 50/18 pt type, exact 38/30 pt leading, paragraph spacing, black paper and registered 79/81/80 bevel/glow treatment remain unchanged. Paired paragraph starts are measured and aligned using ordinary before-spacing. There is no shrink-to-fit. Original approved reference hashes are unchanged and remain an exact pixel/geometry regression; novel prose has its own content-independent presentation check. Font files, inputs, language projects and rendered demos remain ignored.

Native documents stay at **0.5.0**. Forge adds an optional `laboratory` member with its own `formatVersion: 1.0.0`; old five-member snapshots and their hashes remain valid without rewriting commits. M8 is required for the new laboratory extension; a frozen older M7 installation cannot edit those extended projects. Portable history bundles include its definitions and run records; keep proof/run folders and font-complete Workbench backups separately.

Each rendered run records the language commit, test, wiki hash, approved template hash, renderer identity, document/proof hashes and a hash of `language-results.json`. Each suite records engine 1.0.0, snapshot/suite/case hashes, expected and actual outcomes, coverage and detailed analyses. API traces and exceptions remain under `.local/logs`; generated runs retain their manifests and API transcript. No descriptor token belongs in a share image or export.

## API and MCP

API **0.9.0** has **121 operations**. The six additions are `forge.lab.read`, `forge.lab.put`, `forge.lab.remove`, `forge.lab.evaluate`, `forge.lab.run` and `forge.lab.compare`. Draft mutations require `project_id` and `expected_generation`, plus the existing document identity/revision and idempotency envelope. Rule removal fails while references remain. `ui.forge` adds the Laboratory section, result/coverage/diagnostic views, frozen run and comparison selection, and `draft: true` for returning to the editable draft. `forge.test.run` includes the pinned language suite before rendering. All use the same dispatcher as the desktop.

Contracts: `schemas/laboratory-command.schema.json`, `data/laboratory-capabilities.json`, and `data/laboratory-mcp-tools.json`. Headless: `.venv\Scripts\python -m vayrshemon mcp --headless --laboratory`. Live MCP discovers the selected 0.9.0 descriptor; choose it explicitly when several windows are open. M7's `--forge` headless mode is retained.

Rebuild the private demo with `.venv\Scripts\python -m tools.m8_demo --out <new-directory>`. It requires the private M7 history bundle, original input witnesses and approved reference. Public compiler, transaction, API, MCP and Qt authoring tests use synthetic data. The additional soft-verse rendering regression skips when private reference assets are absent. M9 remains explicit branch merges and language release acceptance; general parsing and broader grammar coverage remain future work.
