# M3 — Typesetting and collision workbench

Application/API **0.4.0**; native document **0.3.0**; typesetting policy **0.1.0**. Windows desktop and local files remain the target. M0/M1/M2 contracts are retained.

## Launch and setup

Run `setup.bat`, then `launch.bat`. Setup uses `requirements/requirements-m3.txt`, retains Python 3.12 / Qt 6.8.3, runs dependency checks and every public regression, and records stdout/stderr in `.local/logs/`. No new runtime dependency is needed for M3. `setup.bat --no-pause` is the unattended entry point.

`python -m vayrshemon editor` opens M3. `editor --m2` retains the M2 interface; `lab` retains M1. A running older window keeps its own session until closed. Live MCP discovers the API version in that window's descriptor; opening another window does not discard existing edits.

M3 opens M1 and M2 files by migration. Save the migrated document to a **new path**; the original file is retained. M3 files require the M3 reader. Page dimensions, font locators/hashes, semantic runs, paragraph rules, break profiles, optical rules, collision settings and frame chains participate in the same undo, atomic save and durable recovery system.

## Editing and page layout

The center pane edits the authoritative source story using native input, selection and accessibility. The page on the right shows derived typesetting. Enable it for the selected source frame in **Typeset**. Until enabled, M2 page geometry remains in use. The source pane deliberately retains native editing layout; the right preview and PNG/SVG exports share the derived layout.

- **Text:** exact, minimum or proportional line height; paragraph before/after spacing; alignment, tabs, tracking, word spacing, baseline shift, font and language. These are source formatting choices.
- **Typeset:** distribute extra leading before, after or around the baseline; snap baselines to a page-relative grid; select collision policy and budgets.
- **Flow:** keep selected paragraphs together or with the next paragraph; set minimum initial lines (orphans) and final lines (widows); link empty continuation frames. Text stays entirely in the first frame. Continuations are read-only; use **Edit story source** to edit them. Clicking a laid-out line maps to the original source offset.
- **Breaks:** select a language profile, wrapping strategy and explicit character tailoring. Saving increments its revision. Insert a discretionary soft hyphen, zero-width break or forced line separator explicitly at the caret.
- **Pairs:** compare an isolated pair with font kerning off/on and an optical adjustment. Store a bounded pair rule separately from font kerning, or create an editable dense specimen on a new page.

Linked frames must have equal widths and empty native content. API target order is explicit; the desktop uses document order. Frame heights and page dimensions may differ. Cycles, shared targets, unequal widths and nonempty targets are rejected atomically. Deleting a linked frame/page detaches its links in the same undoable command. The last supplied frame retains overset text and reports overflow; M3 does not create pages automatically.

Paragraph identities survive native edits without putting control characters into the source. Rules for a deleted paragraph are inert; undo restores the original identity and policy. Impossible pagination constraints produce diagnostics rather than deleting lines or resizing type.

## Collision semantics

The inspector distinguishes:

| Bound | Meaning |
| --- | --- |
| Advance | The line's advance box, shared by its glyph records |
| Ink | Conservative rectangle around the union of enabled glyph-layer ink |
| Stroke | Ink expanded by half the reserved stroke width |
| Effect | Stroke bounds expanded by the reserved effect padding |

Stroke and effect settings reserve space only. They do **not** paint strokes, shadows or glows; decorative rendering and portable color-font compilation remain M4.

`allow` records overlaps as informational. `warn` reports them without repair. `repair` can add vertical leading within the configured total expansion and iteration budget. It never edits source characters, glyph sizes, font kerning tables or intentional joined clusters. Grapheme/ligature coverage is grouped before comparison. Unknown joining scripts and adjacent legacy symbols are conservatively protected; an explicit optical legacy pair needs an independence declaration. Combining marks and joiners remain protected even with that declaration.

Clearance applies to conservative rectangles in both axes. Close horizontal letter pairs may therefore need an explicit optical rule even when vertical repair succeeds. This is not an exact outline-intersection or optical-quality score. Cross-frame overlaps require manual frame positioning. Fixed-frame repair rejects a trial that leaves ink or line extents outside any frame in the story, including pre-existing overflow. Turn off that constraint only when retained overset output is intended.

The decisions inspector exposes collision source ranges, protection reasons, before/after counts, expansion totals, changed baselines and solver events. Stable unresolved reasons include `EXPANSION_LIMIT`, `FIXED_FRAME_CONSTRAINT`, `ITERATION_LIMIT`, `ANALYSIS_LIMIT`, `HORIZONTAL_REQUIRES_EXPLICIT_OPTICAL_RULE`, `CROSS_FRAME_REQUIRES_MANUAL_LAYOUT`, and the selected allow/warn policy. Absence of reported collisions is conclusive only when `complete` is true.

## Unicode and shaping

Qt 6.8.3 supplies native shaping, bidi and Unicode grapheme/line boundaries. Language profiles add permitted and prohibited character boundaries; they do not normalize or transliterate source text. Standard wrapping retains an unbreakable word as overflow unless emergency grapheme wrapping is explicitly selected. Automatic dictionary hyphenation is not implemented. The reserved provider contract returns source UTF-16 grapheme offsets and cannot rewrite text.

Format ranges are coalesced before derived shaping so equal-format boundaries do not sever Arabic joins. Fallback runs are sorted into deterministic source order before painting/hashing because Qt can enumerate them differently between processes. Qt line-column counts operate on grapheme clusters; the implementation measures long unbreakable lines before setting their alignment width. Native caret hit testing remains responsible for bidi affinity.

An optical rule applies native letter spacing to the left grapheme and reshapes it; its actual width change can differ from the requested tracking delta because that explicit format boundary also affects pair shaping. The pair explorer reports the measured change. Native shared-glyph ligatures, marks and joining scripts are protected from these rules. The font file and its kerning tables are never rewritten.

Primary references: [Qt Unicode boundary finder](https://doc.qt.io/qt-6.8/qtextboundaryfinder.html), [QTextLayout](https://doc.qt.io/qt-6.8/qtextlayout.html), and [QTextLine](https://doc.qt.io/qt-6.8/qtextline.html). Exact behavior is checked against the pinned 6.8.3 runtime, rather than assuming later Qt documentation describes every edge case identically.

## API, MCP and diagnostics

All **57** operations use the same writer. The twelve M3 operations are:

| Group | Operations |
| --- | --- |
| Policy and paragraphs | `typesetting.read`, `typesetting.configure`, `paragraph.rules` |
| Flow and breaks | `flow.set`, `breaks.profile`, `breaks.inspect`, `breaks.insert` |
| Collision and optical research | `collision.configure`, `collision.inspect`, `optical.set`, `pairs.inspect`, `specimen.create` |

Use `session.status` before mutation. Mutations require the current document ID, revision and a fresh idempotency key over MCP/CLI. Offsets are UTF-16 code units on grapheme boundaries. Distances in policy commands are points; reported glyph/page geometry is logical pixels at 96 DPI.

Published discovery and schemas:

- [Capabilities](../data/typesetting-capabilities.json) and [MCP tools](../data/typesetting-mcp-tools.json).
- [Command schema](../schemas/typesetting-command.schema.json) and [document schema](../schemas/typesetting-document.schema.json).
- Regenerate with `python -m tools.generate_m3_contracts`.

Read-only CLI examples:

```powershell
.venv\Scripts\python -m vayrshemon call session.status
.venv\Scripts\python -m vayrshemon call collision.inspect
.venv\Scripts\python -m vayrshemon call breaks.inspect
```

For mutation parameters prefer `--params-file` to avoid Windows shell JSON escaping. Use `mcp --headless --typesetter` for a separate M3 session; `mcp --headless --editor` retains M2. `inspect` and `render` auto-detect saved M3 files. Setup's `.local/mcp-config.json` still connects to the active desktop session.

The bottom diagnostics tabs and `.local/logs/*.jsonl` expose API traces, Qt errors, recovery durability, layout elapsed time and composition limits. Failed preview calculations leave the source editable and display an actionable error. Proof transcripts, captures and original fonts remain ignored under `.local/` and `Inputs/`.

## Validation and limits

The user-approved [portrait parallel translation page](FORMATTING.md) is now a standard formatting and regression scenario. `test_parallel_translation.py` covers the two independent columns with both public synthetic data and locally available attested passages. The reference preserves the original fonts, aligned paragraph starts, and its documented ink-overhang diagnostic.

The user has not accepted M3's glyph rendering as the final visual quality. The target is `Inputs/Versions Best/Individual Glyphs`; reference-quality bevels, shading, fine edges and glow are explicit M4 VISUAL-01 work. Passing M3's geometry and structural page tests does not close that visual-quality requirement.

[Public tests](../tests/test_m3.py) cover preservation during repair, deterministic undo/reflow, fixed-frame and expansion constraints, leading distribution, fractional grids, paragraph spacing, linked frames, keep/widow/orphan behavior, Unicode controls, Arabic joins, marks, source mapping, optical rules, PNG/SVG output, migration, subprocess recovery and desktop controls. Existing M0/M1/M2 regressions remain required.

Run `python -m tools.verify_m3` with local source fonts for the isolated live-MCP proof. It uses the actual Thimfora 79/80/81 files, verifies mixed source/geometry across UI, save/reopen and headless rendering, checks color versus monochrome output, and recovers after a forced process exit. [The committed report](research/m3-validation.json) contains measurements and hashes; original assets and local output paths are excluded. It does not alter an existing user editor session.

M3 deliberately bounds work: at most 30,000 source scalars per enabled story, 20,000 positioned glyph records per composition, 10,000 lines per story, 200,000 pair comparisons, 10,000 collision records and 16 solver rounds. Pair-comparison exhaustion marks analysis incomplete and stops repair. Larger native documents remain editable with typesetting disabled; M6 retains incremental/background layout and large-document optimization.

Equal-width finite frame chains, vertical-only automatic repair, conservative rectangles, manual hyphenation and page-at-a-time proof export are the supported scope. Exact contour collision, variable-width chains, automatic page creation, PDF/searchable publishing and language dictionaries are subsequent work. External OS candidate-window, UIA-client and physical monitor checks from M1 remain manual validation; these are not claimed by synthetic Qt input tests.
