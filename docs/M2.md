# M2 authoring editor — 0.3.0

M2 builds on the pinned Qt 6.8.3 native input/layout adapter. Application and editor API: **0.3.0**. Native document format: **0.2.0**. M0 semantic documents and the M1 laboratory API/file format retain their previous versions.

## Start and write

Run `setup.bat`, then `launch.bat`. Setup installs `requirements-m2.txt`, checks the environment, and runs the entire public regression suite. Python 3.12, 64-bit is required; 3.12.7 is tested. M2 uses the existing pinned Qt dependencies, including QtSvg; no additional compiler, service, or system font installation is required. Setup logs remain in `.local/logs/` and errors stay visible.

The editor starts with an empty document. It privately loads the source 79/80/81 recipe when the local Inputs archive exists. Use **Text → Load TTF** for other static fonts. Select text, choose its font and language, then apply formatting. A collapsed selection sets the next-input format. The native editing surface shows the selected frame at 100%; the adjacent page preview shows registered color and page placement. Click a frame in the preview or the document tree to edit it.

- **Document:** new/open/save/save-as, recent documents, title, pages, independent text frames, and recovery.
- **Layout:** per-page width/height in points, millimeters or inches; asymmetric margins; frame position/size; show or clip overflow. Frames that exactly match the content area follow page/margin changes. Other frames keep their geometry and must remain inside the page.
- **Text:** font, language, size, RGBA color, tracking and word spacing in points, baseline adjustment in percent, named character styles, left/center/right/justified alignment, paragraph spacing, left tab stops, proportional/exact/minimum line heights, kerning and standard ligatures.
- **Color:** select three compatible source fonts, validate the recipe, change three flat layer colors, and toggle individual layers. Mode and diagnostic overlays are shared with API rendering.
- **Navigation/export:** preview zoom, scrollbars, middle-drag panning, Ctrl+wheel zoom, point rulers, overflow indicators, current-page PNG and outline SVG.

Ctrl+Z/Ctrl+Y undo and redo complete document transactions, including pages, frames, styles and palettes. History retains up to 80 snapshots within 64 MiB. Find/replace searches literal text across frames, supports case/whole-word options, respects grapheme boundaries, and replaces all matches in one undo step. It does not infer transliteration or language-specific word rules.

## Files, recovery and source preservation

Save native documents as `*.vay.json`. Each file includes independently laid-out frames, semantic Unicode/legacy spans, exact font hashes and local locators, character/paragraph attributes, color settings, named styles, revision summaries and an engine fingerprint. Source text is not normalized. Requested spacing values are retained separately from Qt's rounded internal metrics.

Saves use a same-directory temporary file, flush/fsync, and atomic replacement. Saving over the current document first preserves its previous valid contents under `.local/history/<documentId>/<sha256>.vay.json`. An unexpected external file change blocks overwrite. Save-as and exports require a new destination; they never silently replace another file. Inputs, Git internals and loaded font files are protected destinations. Local histories are not independent backups.

Every accepted edit checkpoints the complete current state under `.local/recovery/`. A process lock prevents recovering another live session. **File → Recover interrupted session** restores an abandoned checkpoint, including unsaved text, dimensions, styles and font references. A checksum rejects corrupt state. The source checkpoint is retired only after the new recovery record is durable. If a write fails, the status bar and `session.status` show the error and last durable revision; the previous durable checkpoint survives. Closing after choosing Save or Discard marks that session closed. In-memory undo stacks are not restored after a restart; saved/recovered revision summaries remain inspectable.

M1 `*.vaylab.json` files open through an explicit migration into one independent frame. Saving requires a new M2 path, preserving the original M1 file. Unsupported future file versions fail validation. When opening a document with a missing/moved font, the UI requests the exact original bytes and checks their SHA-256; it does not substitute another TTF. Recovery also accepts a `fontPaths` map through its API for relocated fonts. Fonts are referenced, never embedded or uploaded.

Copy/paste within M2 carries both original plain source text and `application/vnd.vayrshemon.fragment+json` metadata: language, legacy font identity, mapping profile, formatting, and paragraph settings. Other applications receive source text; legacy script text requires its corresponding font. External CR/CRLF clipboard newlines are explicitly converted to LF and logged. Semantic clipboard payloads preserve their original scalar content. Arbitrary HTML/rich-text import is unsupported.

## APIs and MCP

All 45 editor operations have a shared Python, CLI and MCP implementation. Published contracts:

- [Native file schema](../schemas/editor-document.schema.json), with embedded M0 documents additionally validated against the M0 schema and semantic invariants.
- [Command schema](../schemas/editor-command.schema.json).
- [Capabilities](../data/editor-capabilities.json) and [MCP tool definitions](../data/editor-mcp-tools.json).

`setup.bat` writes `.local/mcp-config.json`. Live MCP discovers the active M1 or M2 version and connects through the current-user local socket with a session token. It does not expose a network listener. Every external mutation needs `documentId`, `expectedRevision`, and a fresh `idempotencyKey`. Frame selection advances the revision so a command prepared for another frame cannot edit the wrong text. Offsets are UTF-16 code units on grapheme boundaries within a frame; layout positions are logical pixels at 96 DPI.

```powershell
# Inspect the running editor.
.venv\Scripts\python -m vayrshemon call session.status
.venv\Scripts\python -m vayrshemon call document.read
.venv\Scripts\python -m vayrshemon call recovery.list

# Headless M2 MCP. Omit --document to start a blank document.
.venv\Scripts\python tools/run_lab.py mcp --headless --editor --document .local/example.vay.json

# Inspect or render an existing M2 file without a visible editor.
.venv\Scripts\python -m vayrshemon inspect --document .local/example.vay.json
.venv\Scripts\python -m vayrshemon render --document .local/example.vay.json --out .local/example.png --dpi 144

# Retain access to the original M1 laboratory.
.venv\Scripts\python -m vayrshemon lab
```

For a CLI mutation, place method parameters in JSON and pass `--params-file`, `--expected-revision`, `--document-id` and `--idempotency-key`. Use the values returned by `session.status`; do not guess them. `render.png`, `render.svg` and `layout.inspect` accept `page_id` for a specific page. MCP tool names replace punctuation with underscores, for example `document_save_as` and `paragraph_format`. Default headless MCP retains M1 compatibility unless `--editor` or an M2 file is supplied. A headless process ending without a save leaves its unsaved recovery checkpoint available.

## Evidence

`tests/test_m2.py` exercises fractional pages and asymmetric margins, complete undo, stale frame guards, partial formatting, exact-spacing preservation, empty-frame insertion formats, semantic/native clipboard, find/replace, styles/features, atomic saves/backups, external changes, M1 migration, exact font relocation, forced process termination, failed recovery writes, invalid files, native typing/IME events, PNG size, SVG clipping via a separate SVG renderer, and MCP/discovery contract parity. M0 and M1 tests continue to run.

With the original Inputs archive available, run:

```powershell
.venv\Scripts\python -m tools.verify_m2
```

The runner uses a separate native session and local socket. It creates a real two-page mixed English/Thimfora document through live MCP, changes dimensions and color, checks semantic and geometry equality after reopening and headless inspection, captures the native window, exports PNG/SVG, then forces its own child process to exit and recovers the unsaved mixed document through MCP. It never changes the active user session. Outputs, source-font screenshots and the full MCP transcript stay in ignored `.local/m2-proof/<run>/`. The committed [validation report](research/m2-validation.json) contains only measurements and font hashes.

## Boundaries

- Frames are independent; automatic cross-frame flow, pagination, collision avoidance/repair, widow/orphan rules and baseline grids remain M3 or later. Overset text stays intact and is explicitly shown or clipped.
- Page dimensions are positive up to 1,000,000 points; practical documents must have usable margins and frames. Current guards allow 100 pages, 32 frames per page/128 total, 100,000 scalars per frame/200,000 total, 8 MiB serialized state, 16 MiB files and 128 font sources. Full-state history/checkpointing favors correctness for small documents; these caps are not a large-document performance guarantee.
- PNG is bounded to 16 million pixels and 32,767 pixels per edge. Use a region for larger pages. SVG is an initial pure-outline proof with physical dimensions and baked clipping; it has no searchable/copyable text and rejects bitmap-only glyphs. Portable font compilation, PDF and full publishing preflight remain M4.
- Named styles are applied formatting presets; editing a preset does not restyle prior text automatically. Tab support is left stops. Recipes use three compatible static fonts and flat fills; gradients, glow/bevel and COLR/CPAL generation remain M4.
- Semantic text and exact source font identities round-trip. System fallback font metrics can differ across machines; geometry comparisons apply to the recorded engine/font environment.
- The native IME event path and Qt accessibility provider are tested. Physical OS candidate windows, external screen-reader/UIA clients and physical monitor-DPI switching retain the manual validation limitations recorded in M1. Language grammar/lexicon/corpus tooling remains M5.
