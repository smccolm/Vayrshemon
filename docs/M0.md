## Mapping decisions and remaining uncertainty

The 79/80/81 profile is tied to the exact three font hashes. It must not be applied to Test Seven, transliteration 5, transliteration 7, or an older font merely because a name looks related. The layer fonts share character-to-glyph assignments; their shared advance/positioning evidence is recorded in the earlier [font-layer audit](research/font-layer-audit.json). Actual rendered registration is still an M1 check.

Every letter form and digit has chart source/hash, row locator, and mapping confidence. Human name transcriptions have their own confidence; they are not asserted to be finalized pronunciations or IPA. Three letter transliterations remain unresolved at ordinals 12, 21, and 45 because the chart's special Latin forms need an exact Unicode transcription. Their script identities and legacy code slots are known, so this does not prevent lossless editing of their legacy representation.

The 13 remaining non-space cmap slots have known glyph IDs and glyph-name hints, but their linguistic punctuation/clitic function is unverified. They remain unresolved rather than inheriting a meaning from a Latin glyph name. Space and no-break space retain distinct source scalars even though they share a glyph.

`Versions Best/Polished Examples.docx` has 22 paragraphs and 179 runs in the evidence extraction. It references **test seven** and **transliteration 5**. File candidates are recorded by name without claiming that a name match proves the exact original font bytes. The extractor retains relevant XML parts, direct font properties, text tokens and unsupported-node evidence. It is not a complete Word importer: style/theme inheritance, revision visibility, fields and semantic mapping remain unresolved. Its observed `lastRenderedPageBreak` node is preserved and reported.

Historical mapping profiles, original design-layer internals, phonetic interpretation, final punctuation behavior, and a separate archive backup remain open work. No source files were converted, font tables repaired, or language rules silently selected. The M0 exit gate allows explicitly unresolved mappings; resolving these questions is separate from preserving the evidence.

## Run the tools

The current `setup.bat` installs both M0 evidence tools and the M1 native lab. The manual M0-only instructions below remain available for evidence work without Qt. See [M1](M1.md) for the launcher and live API/MCP interface.

On Windows, double-click [`setup.bat`](../setup.bat), or run `./setup.bat --no-pause` from PowerShell for automation. It finds Python **3.12, 64-bit** on PATH or through the `py` launcher, creates or reuses `.venv`, installs the exact versions in `requirements-m0.txt`, checks dependency compatibility, validates the evidence/contracts, and runs the test suite. Python **3.12.7** is the pinned CI/tested environment; setup accepts other 3.12 patch releases and records the actual version in its log.

Setup uses Windows PowerShell's built-in transcript to show and save output, including failures, in `.local/logs/setup-*.log`. Evidence checks also save structured `.jsonl` diagnostics there. It works when launched from another directory, pauses before closing by default, and exits nonzero on failure. Rerunning is supported. If Python is missing, it explains the prerequisite; if an existing `.venv` is incomplete or incompatible, it stops without deleting it. The first dependency install needs internet access to the configured Python package index. No compiler or desktop runtime is needed for M0.

For a manual installation with Python 3.12.7:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-m0.txt
.venv\Scripts\python -m tools.m0 check
.venv\Scripts\python -m unittest discover -s tests -v
```

Subsequent examples use `python`; activate the environment first with `.venv\Scripts\Activate.ps1`, or substitute `.venv\Scripts\python.exe` without activation. Linux uses `.venv/bin/python`. The implementation was checked locally using Python 3.12.7 and the listed package versions. Tests use ordinary inherited permissions inside `.local/test-work/`, which also works under Windows restricted tokens.

These checks require **no Inputs folder**. The GitHub workflow runs them on Windows and Linux with pinned action commits and Python version. Public tests generate their own simple font geometry; no original font binaries are uploaded.

Rebuild evidence from the local archive, in dependency order:

```powershell
python -m tools.m0 --log .local/logs/catalog.jsonl catalog --out data/assets.json
python -m tools.m0 --log .local/logs/fonts.jsonl fonts --out data/fonts.json
python -m tools.m0 mapping --out data/orthography/thimfora-79.json
python -m tools.m0 fixtures --out data/fixtures.json
python -m tools.m0.schema_definitions
python -m tools.m0.synthetic
python -m tools.m0 check
python -m tools.m0 verify-assets --all
```

Generation is deterministic for unchanged sources and dependency versions. `check` detects stale generated schemas and mappings, invalid data, missing references, and malformed public documents. `verify-assets` defaults to the selected source set; `--all` hashes the entire archive and reports added, changed or missing files. Original inputs are read only. Output and log paths inside the archive are rejected.

Preserve the legacy example's DOCX evidence locally:

```powershell
python -m tools.m0 --log .local/logs/docx.jsonl extract-docx "Inputs/Versions Best/Polished Examples.docx" --out .local/polished-examples.json
```

Decode a legacy text fixture with its explicit Windows-1252 codec and the exact master font identity:

```powershell
python -m tools.m0 decode-legacy "Inputs/Versions Rough/Test Sequence - Times New Roman.txt" --encoding cp1252 --font-sha256 a9bb4075285df9acf2bf75c08446d44cfd83b29f6940937671cc07bd68f9f6cc --out .local/decoded-sequence.json
```

The result preserves original bytes as base64, original Unicode text, per-scalar offsets, and unresolved positions. Undecodable bytes fail explicitly without replacement or codec guessing. `restore_legacy` verifies the scalar round trip; the retained bytes preserve the original encoding and line endings.

## API and schema boundaries

The Python functions in `tools/m0/` are callable APIs for the evidence CLI. The CLI keeps JSON results on stdout and correlated JSONL events, library warnings and exception stacks on stderr; `--log` also saves them. Each invocation has a trace ID. No live MCP transport is advertised yet.

The initial document schema separates pages/frames from stories/paragraphs and distinguishes Unicode runs, canonical symbol runs and preserved legacy runs. Dimensions use decimal strings of integer micro-points, checked against signed 64-bit bounds; this avoids JavaScript integer precision loss. Style and frame references are checked separately from structural JSON validation. Language/script identifiers are internal IDs, not claims of registered language codes.

The command schema drafts revision-checked, idempotent transactions and revision-bound queries. It does not execute edits, enforce a live session revision or implement undo yet. A valid request is not proof that an operation is supported: clients must check [capabilities](../data/capabilities.json). The current operations cover text insertion/deletion and page dimensions; more operation types will be added as M1 establishes editing semantics. `dryRun` is a request-contract field; its execution/result behavior must be finalized with the command runtime before it is advertised.

JSON Schemas use [Draft 2020-12](https://json-schema.org/draft/2020-12/release-notes) with an offline registry. Font inspection uses the pinned [fontTools TTFont API](https://fonttools.readthedocs.io/en/latest/ttLib/ttFont.html). This tooling reads metrics and mappings; it does not execute shaping or establish pixel rendering baselines.
