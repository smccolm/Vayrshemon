# M9 — Language merges, releases and dependable PNG export, 0.10.0

M9 adds explicit language integration and release evidence to the Forge. Single-page Workbench views center after opening, resizing, zooming or changing the left panel. The preview toolbar replaces Fit Page with **Fit Height** and **Fit Width**. Each fits the corresponding page dimension to the available preview (within the existing 10–300% zoom range); Fit Width permits vertical scrolling. Both center the view without changing page geometry. Hand panning remains available and survives normal refreshes; Center page or a viewport change recenters it. This changes view coordinates only. The approved page dimensions, margins, type, registered three-font paint and native document format are unchanged.

`setup.bat` installs the existing pinned runtime through `requirements-m9.txt`, audits dependencies and runs the full regression suite. No new external dependency is required. The default launcher opens M9; `launch.bat --m8` retains the M8 interface. Earlier flags remain supported.

## Merge language branches

In **Language Forge → Merges**, choose a source branch and Preview merge. The active branch is the destination and must have a committed draft. The source's frozen head is used; its uncommitted draft is retained separately. The preview identifies both heads, the common ancestor, the project generation and each conflict's base/active/source values. Missing records are distinguished from JSON null.

Independent edits merge by stable record ID and field, including dictionary senses, wiki pages, language rules and test cases. Ordinary ordered arrays such as word order, witnesses and paired paragraphs are atomic. A delete-versus-edit or incompatible edit requires a choice. The UI offers Active branch, Source branch, Base or Delete. The API additionally accepts an explicit custom JSON value. Every conflict must be resolved, and the resulting snapshot must pass all reference and clause-to-page binding checks.

Commit resolved merge creates one immutable commit with **both parents**, the base and the recorded choices. It atomically advances only the active branch. Failed validation, stale project generations, changed previews and unresolved/unknown choices leave the project unchanged. An already-contained source is rejected as a no-op. Unrelated histories and ambiguous criss-cross merge bases are deliberately unsupported; M9 never guesses a base. Histories are bounded to 10,000 visited commits per ancestry traversal.

## Freeze language releases

Run the selected frozen language version in **Laboratory** and **Tests → Run frozen version in Workbench**. The latter requires a page whose displayed script is bound to the exact clause cases. Then open **Releases**, select that version and its two runs, enter a unique name, channel and notes, and Create immutable release.

A release pins the content-addressed language commit: its dictionary, rules, wiki, tests and editorial decisions. It embeds the suite and Workbench reports, source/proof hashes, known gaps, channel and acceptance status. Creating a release checks the actual saved manifests, document, PNG and language report, and recomputes the selected version's suite. Wrong-version evidence, tampered artifacts, empty suites and unexpected test failures are rejected. Later branch movement cannot change a release. Release names are unique; no edit/delete command exists, and SQLite prevents release updates and deletion.

**Experimental** releases retain review and unsupported outcomes, with explicit notes; they are proposals, not language-author acceptance. **Stable** requires all suite/page checks to pass, no grammar outside the executable scope and a named accepting reviewer. The present literary demo cannot meet that gate: meaning review, the general parser and conservative collision warnings remain open. M9 does not manufacture an acceptance or waive these checks. A richer scoped human-review/waiver workflow remains future work.

Export selected release writes a portable JSON artifact containing the frozen dictionary/wiki/rules/cases and embedded evidence. It records proof/font references without bundling those binaries; retain the run directory and Workbench font-complete backup for visual reproducibility. Export history/restore also retains both parents, branch drafts, release records and all existing run records.

Projects remain Forge **1.0.0** until a merge or release is committed, when the envelope becomes **1.1.0** atomically. M9 reads both. Earlier executables reject 1.1.0 rather than silently discard its additional graph/release data. Historical commit hashes are not rewritten. Native books stay **0.5.0**; paint engine stays **1.1.0**.

## PNG button

The enlarged approved page exceeds the 16-million-pixel renderer limit at the old 300 DPI default. The M9 button chooses the highest supported whole-number DPI at or below the requested setting: **292 DPI, 3511 × 4543 pixels** on this page. The save-dialog title and status message show the actual DPI, and the trace records requested/actual settings. It preserves the approved font treatment and page geometry.

PNG and SVG suggestions retain local date/time through milliseconds. A missing file suffix is added. Replacing an existing image requires explicit confirmation; the old file stays intact until rendering succeeds. Its hash is checked again before atomic replacement, so a change made during rendering causes a visible failure instead of being overwritten. New destinations still use exclusive creation. Worker status, progress, output path and logs remain in Reliability. The API continues to honor explicit DPI, including rejecting oversized requests; the desktop does not raise the renderer memory limit. Very large pages that cannot fit even at 72 DPI require a bounded-region export or another page size.

## API, MCP and diagnostics

API **0.10.0** exposes **127 operations** through the common guarded dispatcher. New controls are `forge.merge.preview`, `forge.merge.apply`, `forge.releases`, `forge.release.read`, `forge.release.create` and `forge.release.export`. Mutations retain document identity/revision/idempotency guards; language writes also require `project_id` and `expected_generation`. Merge apply requires the preview's `plan_id` and a path-to-choice map. `ui.forge` supports Merges/Releases, `merge_source` and `release_name`. `ui.workspace` adds mutually exclusive `fit_height` and `fit_width`; its legacy `fit_page` parameter remains for existing clients. `jobs.export` adds optional `replace_sha256` for explicit guarded replacement.

Contracts: `schemas/integration-command.schema.json`, `data/integration-capabilities.json`, `data/integration-mcp-tools.json`. Regenerate with `python -m tools.generate_m9_contracts`. Headless controls: `python -m vayrshemon mcp --headless --integration`. Live MCP discovers a 0.10.0 descriptor; specify the descriptor when multiple editors are open. No private descriptor tokens belong in exported artifacts.

Validation evidence is recorded in `docs/research/m9-validation.json`. Public tests cover conflict resolution, stable IDs, delete/edit conflicts, stale writes, retained drafts, two-parent ancestry and bundle restoration, immutable releases, evidence tampering, release gates, API idempotency, MCP tools, actual Qt merge controls, centering, PNG replacement and concurrent destination edits. The private PNG-button test exports and decodes the approved enlarged page; normal setup also runs both approved formatting regressions.

Setup completed with **173 tests passing in 387.703 seconds**. After the final fit-control and Forge-envelope changes, **34 focused checks passed in 94.387 seconds**, including the new fit-button regression, M7/M8 compatibility, actual PNG output and parallel translation. The unchanged approved baseline also passed its exact state, geometry and RGBA comparison.
