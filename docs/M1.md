# M1 — Native font, rendering, and input laboratory

Implemented 2026-10-22. Application/API **0.2.0**, lab-file wrapper **0.1.0**, Qt/PySide **6.8.3**, tested Python **3.12.7**. M0 contracts and evidence remain version 0.1.0. This checkpoint proves a native adapter and control surface; M2 is the full authoring workflow.

## Start and update

Double-click [`setup.bat`](../setup.bat), then [`launch.bat`](../launch.bat). Setup installs the exact [M1 requirements](../requirements-m1.txt), including M0 requirements, in `.venv`; checks package compatibility and M0 evidence; and runs the native/public regression suite. Python 3.12, 64-bit is the prerequisite. No compiler, Rust, Node, global font installation, or system-wide Qt installation is required.

Setup is repeatable. Each run keeps a console transcript in `.local/logs/` and writes `.local/mcp-config.json`. `setup.bat --no-pause` supports automation. New dependencies belong in the pinned requirements and this same setup path. Save a running lab document before restarting to load a code update; setup does not close the user's window.

## What works

| Surface | Implemented behavior |
| --- | --- |
| Native editor | English, Unicode, and explicit legacy/script spans; keyboard/pointer selection, horizontal/vertical movement, plain-text clipboard, native text/format undo and redo, preedit/commit input events |
| Page | Independently entered width and height in points, mm, or inches; fractional micro-point storage; explicit overflow indication |
| Fonts | Local static TTFs identified by SHA-256; process-private aliases distinguish identical family names; original files remain unchanged; missing/changed source hashes fail explicitly |
| Color | Thimfora 79 master plus 80 base and 81 interior, validated glyph-name/cmap/advance mappings, master origins reused for every layer; visibility and flat color controls through API |
| Comparison | Editable monochrome pane, color preview with zoom/pan, and a bounded reference-image view |
| Inspection | Source ranges/scalars, glyph IDs, selected/actual fonts, fallback reason, nominal advances, cluster advances, positioned origins, ink bounds, baseline-relative offsets, kern/liga flags, origin/baseline/bounds overlays |
| Persistence | Validated `*.vaylab.json` files, atomic replacement, save/reopen semantic and geometry equality, external-change detection, source-output protection |
| Automation | Python session API, CLI, current-user local socket, and stdio MCP use the same Qt-thread writer; document IDs, revisions, and idempotency protect mutations |
| Diagnostics | Correlated JSONL component logs, native accessibility inspection, layout JSON, local widget capture, PNGs, and reproducible measurement runner |

The default demo uses the actual local 79/80/81 fonts and the source reference image when Inputs is present. Without the archive, the lab opens an English demo and accepts local TTFs. The default save location is `.local/`; source fonts are referenced by hash/path, not embedded. Font locators make local reopening practical, but moving a document to a different computer may require resolving its exact source files.

Select a range, choose a font, language and point size, and use **Apply to text**. With no selection, it sets the next input format. Existing source codes are not inferred to be language data merely because their Latin labels look familiar. A Vayrshemon span retains its exact legacy codes and font/profile binding. Unknown mapping semantics remain unknown.

## Adapter and source mapping

M1 uses native QTextEdit input/accessibility with one QTextDocument/QTextLayout authority for layout. The color preview and headless renderer consume its positioned glyphs; no browser text measurement or per-frame bitmap IPC is involved. This replaces the provisional, unimplemented Tauri/Skia route. It does not claim that Tauri failed a test. See the [Qt text layout](https://doc.qt.io/qtforpython-6.8/PySide6/QtGui/QTextLayout.html) and [native editor](https://doc.qt.io/qtforpython-6.8/PySide6/QtWidgets/QTextEdit.html) interfaces.

A local regression reproduced incorrect `QGlyphRun.stringIndexes()` values around emoji fallback in Qt 6.8.3. The inspector therefore recovers source coverage by native grapheme-range queries, unions ranges that share a positioned glyph, and handles split ligatures. It never presents the known-bad indexes as reliable. Caret/selection still use Qt's native editing/hit-testing machinery. API offsets are explicitly UTF-16 code units and mutations reject surrogate/grapheme splits.

Inspector offsets are glyph origins relative to the cluster caret and baseline, not raw HarfBuzz buffer offsets. Nominal glyph advance and positioned cluster advance are separate fields. System-default/fallback fonts are explicitly identified as platform-dependent. Register an exact English TTF as well if its historical geometry must be pinned independently of OS fonts.

## CLI and MCP

```powershell
.venv\Scripts\python -m vayrshemon lab
.venv\Scripts\python -m vayrshemon inspect --out .local/layout.json
.venv\Scripts\python -m vayrshemon render --out .local/page.png --dpi 144
.venv\Scripts\python -m vayrshemon render --out .local/tile.png --region 0 0 512 256
.venv\Scripts\python -m vayrshemon call session.status
.venv\Scripts\python -m vayrshemon call ui.inspect
.venv\Scripts\python -m vayrshemon benchmark --out .local/measurements.json
```

Output files must be new paths unless saving the same previously opened/saved document with an unchanged disk hash. Regions use logical pixels at 96 DPI. Add `--document path.vaylab.json` to inspect/render/benchmark an existing lab file. `--no-source-fonts` starts a public demo without reading Inputs. Windows headless rendering uses a hidden native QApplication because Windows Qt's offscreen plugin has a dummy font backend; Linux uses offscreen.

Setup's `.local/mcp-config.json` is generic stdio MCP configuration with absolute interpreter/script paths. The default MCP process attaches to the latest live lab; `--descriptor .local/run/session.…json` selects a specific window. To run an independent headless session, add `--headless` to its arguments. The absolute entry point works from an unrelated client working directory:

```powershell
.venv\Scripts\python tools/run_lab.py mcp
.venv\Scripts\python tools/run_lab.py mcp --headless --no-source-fonts
```

Protocol revision is **2024-11-05**. Stdout contains only newline-delimited JSON-RPC; diagnostics use stderr and local JSONL files. Discovery is published in [mcp-tools.json](../data/mcp-tools.json), [lab-capabilities.json](../data/lab-capabilities.json), and the [command schema](../schemas/lab-command.schema.json). The standard [stdio transport](https://modelcontextprotocol.io/specification/2024-11-05/basic/transports) and [tool interface](https://modelcontextprotocol.io/specification/2024-11-05/server/tools) are implemented.

Read `session_status` first. Mutating tools require its `documentId`, `expectedRevision`, and a fresh `idempotencyKey`. Retrying the same request/key returns the previous result; reusing a key with a different request is rejected. A live file reopen advances the session revision, so commands prepared before reopening cannot become valid again. Keys are retained for the session, with an explicit 4,096-key capacity. Automation is blocked during native IME composition. Local IPC uses current-user OS permissions plus an ephemeral token, not a network listener. A test session never replaces the active user-window descriptor.

For CLI mutations, use `--document-id`, `--expected-revision`, and `--idempotency-key`. Supply parameters with `--params-file path.json` to avoid Windows shell quoting ambiguities. For example, a document.edit parameter file is `{"start":0,"end":0,"text":"Hello "}`. `document.open` requires `discardUnsaved:true` when replacing unsaved edits. Text/format undo is native; page dimensions and lab settings do not yet participate in document-wide undo.

The M0 `document.apply` draft and its scalar/run-addressed schema remain a versioned evidence contract. The implemented M1 API is 0.2.0 with explicit UTF-16 ranges; it does not pretend the earlier draft is executable unchanged. M0's capability snapshot links to the live M1 matrix.

## Evidence and limits

The [versioned measurement report](research/m1-validation.json) records the reference machine, engine, font hashes, geometry hash and measurements. Original artwork, widget captures, monochrome/color/overlay PNGs, a roundtrip document, and the detailed report remain in its ignored `.local/m1-proof/…` directory.

The final local native benchmark passed UI/headless geometry equality, actual source fonts, native accessible text, preedit/commit behavior, save/reopen equality, and DPI-independent geometry. The 40-key sample measured approximately **2.8 ms p95** to native paint; a 512×256 tile measured **0.4 ms p95**. A full inspector refresh takes about **25 ms** and is debounced. These are local observations, not cross-machine guarantees. The 100,000-character case is substantially slower; the report retains that result. The 100-page experiment measures 100 independent page layouts, not a multi-page flow editor.

Explicit M1 limits:

- One page, one story, one full-content frame, equal margins, visible overflow; dimensions up to 1,000,000 points; 100,000 Unicode scalars and 2,000 styles.
- PNG requests are limited to 16 million pixels and 32,767 pixels per edge. Huge pages use region/tile requests; no giant page bitmap is allocated automatically.
- Static TrueType outlines only, up to 128 loaded font files / 256 MiB of source data. Variable fonts, general font fallback policy, automatic missing-font recovery, and native symbol-sequence editing remain later work.
- Flat registered colors are not a recreation of Photoshop bevel/glow and are not yet a portable COLR/CPAL font. Those remain M4.
- Lab files include local font paths; crash journaling, migrations, rich semantic clipboard, full save-as/recent-file workflow and multi-page recovery are M2.
- Unsupported NUL, CR, U+2029 and lone surrogates are rejected rather than silently lost. Use LF for paragraph breaks. Unicode normalization is not performed.

Native Qt IME preedit/commit events and its accessibility text provider were tested. An installed Windows IME candidate-window interaction, an external UIA/screen-reader client, and movement between physical monitors still need a manual pass. Computer-use app approval timed out during external UIA inspection; the successful proof is the native provider and application tests, not an asserted external inspection. These qualifications stay visible before using the laboratory as a primary authoring tool.

## Regression and dependency discipline

```powershell
.venv\Scripts\python -m tools.m0 check
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python -m tools.m0 verify-assets
.venv\Scripts\python -m tools.generate_m1_contracts
```

The complete Windows setup passed **47 tests** (26 M0 and 21 M1). Public tests build synthetic fonts and do not require Inputs. Native Windows tests require a normal user desktop token for clipboard and current-user IPC; restricted agent tokens can reject those OS operations. Clipboard test contents are restored. The benchmark uses a separate temporary session and never edits the user's open document. Source-derived screenshots and debug bundles are not uploaded automatically.

Qt for Python's pinned Essentials package supplies the required modules. Its distribution/license information is available on the [official package page](https://pypi.org/project/PySide6-Essentials/6.8.3/); a redistributable application packaging/license audit remains part of M6. Run setup after dependency changes, keep the same launcher current, and record changed geometry/performance evidence before tagging another checkpoint.
