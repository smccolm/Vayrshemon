## Orthography workflow

In **Language Forge → Orthography**, select a bilingual page and **Preview Maxima**. The preview shows exact paragraph/scalar positions, letter identities and before/after glyphs. **Apply reviewed preview** saves a guarded draft change, clones the bound clause assertions, preserves earlier cases, and updates the page and its bindings atomically. One mapped scalar replaces one scalar, retaining token offsets. Changing the project, generation, policy or source invalidates the preview. Unsupported initial characters or ambiguous bound-clause boundaries stop the apply rather than guessing.

**Letter pairs** displays the version's full inventory using the local master font. **Policy** edits versioned JSON without rewriting text. **Inspect initials** reports missing or unresolved capitals; **Freeze audit** records the selected committed version and exact input hashes. Historical views are read only. The default policy uses Maxima at paragraph/sentence starts after `.`, `!` or `?`, skips configured quotes/brackets, and does not capitalize every wrapped line. Semicolons and ordinary newlines do not reset the sentence. Interior spellings are preserved. Abbreviations, proper names and more elaborate sentence interpretation remain editorial work.

The chart and Individual Glyphs establish paired shapes. Historical polished examples also show sentence-initial Maxima. The complete M11 punctuation policy is a **proposal**, not a claim that the small archive establishes every capitalization convention. The versioned wiki records that distinction and the source hashes.

## Natural variation

The new **Variation → Orders in context** inspector shows retained orders alongside available or blocked alternatives. The demo proposes subject-first order when an established subject is the noncontrast topic in literary register. Two alternatives cover a nominal predicate with or without an adverb. Existing orders remain available; case, lexeme and feature constraints still apply. Wrong or missing context blocks the new order. Context is an author's analysis, not something the program infers from English.

Two clauses in the coherent Tempest passage use the new option. The subject is already in discourse; moving it first makes that continuity explicit. This is optional information structure, not random shuffling or a requirement to avoid all repetition. M10's shorter forms, full forms, event nominalizer, lexical identities and historical frequency evidence remain. The new revision also corrects the inherited `attested` label on M10's expressly proposed discourse rule to `draft`; the historical commit is unchanged.

Watched-prefix counts now fold only explicit Maxima/Minima pairs. Both versions in a comparison use the same pair map and watch definitions. Stored text and exact-word counts remain literal. In the demo, the watched prefix still occurs **5 times among 29 tokens**; its clause-opening count changes from **3/8 to 2/8** because of the topic order, not because capital letters were miscounted. No frequency threshold is presented as proof of naturalness.

## API, persistence and setup

Seven operations bring the shared desktop/CLI/MCP surface to **140**:

| Operation | Purpose |
| --- | --- |
| `forge.spelling.read` | Read the versioned policy and mapped pairs |
| `forge.spelling.replace` | Validate and save a guarded policy draft |
| `forge.spelling.preview` | Inspect exact proposed edits without mutation |
| `forge.spelling.apply` | Apply the exact reviewed plan atomically |
| `forge.spelling.audit` | Inspect the selected page's sentence initials |
| `forge.spelling.run` | Freeze version-pinned spelling evidence |
| `forge.variation.orders` | Inspect retained and context-gated orders |

`ui.forge` supports `section="Orthography"`, `spelling_test`, `spelling_preview` and `spelling_run`. Use `mcp --headless --spelling` for headless controls; live MCP recognizes 0.12.0. `launch.bat --m10` retains the preceding interface. Contracts are in `schemas/spelling-command.schema.json` and `data/spelling-*.json`.

Spelling policy, lab cases and wiki travel together in Forge history and merges. Test pages pin spelling evidence; named releases recompute and verify it, including its file hash. Older executables reject newer Forge envelopes instead of silently dropping definitions; merges/releases cannot downgrade them. Compiled analyses stay bounded at 100,000, with 128 analyses per surface; spelling supports up to 512 explicit pairs and 32 form rules. M11's public tests use structural fixtures, not invented Vayrshemon.

`setup.bat`, `tools/setup.ps1`, dependency auditing, release verification and CI use the pinned `requirements/requirements-m11.txt` chain. No new dependency is introduced. Setup runs all public checks, including `test_parallel_translation.py`, and retains a separate transcript. Final results, live controls, baseline checks and private artifact hashes are recorded in [M11 validation](research/m11-validation.json).
