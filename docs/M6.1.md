# M6.1 — Collapsible controls and the approved visual baseline

Application and API **0.7.1**, 2026-10-23. Native documents remain **0.5.0**; paint engine **1.1.0**, language format and dependency pins are unchanged. Run `setup.bat`, then `launch.bat`.

The left controls have three states: pinned open, temporarily open, and collapsed. The edge arrow is always visible. Collapse unpins; Expand opens temporarily; Pin keeps the controls open. Clicking the page or source editor dismisses an unpinned panel after the click is handled. Focus changes, typing, dropdowns and modal dialogs do not dismiss it. Selecting a panel through View/Language menus or `ui.workspace` reveals it.

**Ctrl+Alt+B** expands/collapses; **Ctrl+Alt+P** pins/unpins. The buttons expose accessible names and checked state. The View menu includes both shortcuts. A collapsed splitter cannot hide the 40-pixel expansion rail. Dragging the splitter remembers the expanded width (320–560 logical pixels).

Pin state, visibility, expanded width and selected tab are stored atomically in `.local/workspace/sidebar.json`, separately from documents. Preferences apply to this project installation; the last changed window supplies subsequent startup preferences. Existing windows retain their own state. Corrupt preferences fall back to visible, pinned controls with an inspectable error. A preference write failure leaves the controls usable and reports the error in logs, status and API results. No panel action changes document revision, dirty state, text, page dimensions, margins, font sizes, paint, language, zoom or undo history. Fit page remains an explicit command.

## API and MCP

There are now **98** operations. `ui.sidebar` accepts optional `expanded`, `pinned` and `width` fields and uses the existing document/revision/idempotency guard. `pinned: true` expands; `expanded: false` unpins. Requesting both simultaneously is rejected before any change. `ui.sidebar.inspect` returns state, remembered/actual width, selected panel, shortcuts and any preference error. Both require a desktop. `ui.inspect` also includes the panel in `workspace.sidebar`.

Live MCP recognizes both 0.7.0 and 0.7.1 sessions. Connecting to an older running M6 window advertises its original 96 operations. Headless M6.1 advertises desktop-only methods but returns `DESKTOP_REQUIRED` when invoked, as documented in the capability registry.

## Approved reference

Its immutable manifest is [approved-workbench-20261023.json](../data/formatting/approved-workbench-20261023.json). The approved source, PNG and verified font-complete backup remain private under `.local/baselines/visual.workbench.2026-10-23/`.

The page is **865.498700 × 1120.057141 pt** (approximately 12.02 × 15.56 inches), twice the original standard's area. It has two independent full-height columns, 50 pt Vayrshemon and 18 pt English, matching paragraph starts, black paper and the approved blue 79/81/80 treatment. No title, headings or footer are added. The manifest pins exact geometry, font identities, paint settings, protected document-state hash, geometry hash and 144-DPI RGBA pixels. It contains no source passages or font bytes. This acceptance covers the demonstrated page and treatment; the broader Individual Glyphs inventory coverage remains separately tracked.

Changing expected hashes is never automatic. A proposed visual change needs an explained comparison and explicit user acceptance before a new baseline is recorded. The reference copy is separate from the user's editable document, so ordinary edits and zoom saves cannot replace it.
