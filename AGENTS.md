# Project working standards

Use [the approved parallel translation standard](docs/FORMATTING.md) for bilingual demos, formatting examples, and regression work unless the user asks for a different layout. It is a portrait page with exactly two full-height, independent text columns: Vayrshemon on the left and its English translation on the right. Do not add a title, column headings, or a footer by default.

The current approved demonstration baseline is the enlarged 865.498700 × 1120.057141 pt page recorded in `data/formatting/approved-workbench-20261023.json` and `docs/M6.1.md`. On 2026-10-23 the user explicitly approved its font size, page size, margins and font quality. Preserve that exact page/treatment for workbench UI regressions; keep the original 612 × 792 pt fixture as an additional standard regression. Never automatically replace approved state, geometry or pixel hashes. The private reference and font-complete backup live separately from editable demos under `.local/baselines/`.

Use attested source/translation pairs and the original hash-identified script fonts. Synthetic test strings are structural test data, never invented Vayrshemon. Keep original Inputs, extracted text, proofs, and local documents ignored.

For Individual Glyphs color proofs, use the actual Thimfora 79 outline, 81 interior and 80 glow fonts per `Inputs/font files/How to Make High Quality Color Text with Photoshop.txt`. Shape the 79 master once and paint all three at its exact origins, baseline and em scale; never center layers independently. ADD the 81 subpaths before filling. A derived single-font treatment does not satisfy this requirement. Preserve archival imports; an explicitly documented review copy may adopt the three-font family and its recorded encoding adaptation. The user's 2026-10-23 correction rejects the single-font M4 demo and counter-only patch as the requested effect.

Visual-quality target: `Inputs/Versions Best/Individual Glyphs`. M3 rendering was rejected; the subsequent actual-three-font treatment on the enlarged page has now received explicit approval. Preserve that accepted result. Full reference-inventory coverage remains distinct from this page acceptance; follow the remaining M4 VISUAL-01 criteria without changing the accepted baseline implicitly.

For changes affecting authoring, layout, fonts, persistence, or export, include `test_parallel_translation.py` in validation. It is included in the normal unittest discovery run used by setup.bat. Read the standard's limitations before claiming automatic translation alignment or a clean collision report.
